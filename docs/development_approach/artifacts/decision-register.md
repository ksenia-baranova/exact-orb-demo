# Единый реестр решений

Для каждого change реестр является разделом общего Manager-артефакта
`docs/project_management/change_plans/<change-id>/manager_artifact.md`. В нём вопрос проходит весь путь от обнаружения до решения.
Исторические реестры сохраняют свои опубликованные пути.
Новый идентификатор после принятия решения не создаётся: одна строка `DP-*` хранит вопрос, варианты, рекомендации,
решение владельца и подтверждение.

Ролевые requirements, планы и handoff не повторяют содержание строки. Они указывают baseline реестра и нужные
идентификаторы `DP-*`. Так рекомендация одной роли не превращается в решение из-за копирования в чужой документ.

Если выбор меняет архитектурные границы, строка связывается с ADR. Действующий ADR остаётся источником архитектурного
контракта, а реестр показывает, какой вопрос привёл к нему и где находится решение.

## Статусы строки

Значения и переходы DP определены в [process.md](../process/process.md), раздел 4. Manager фиксирует состояние строки на основании достаточности материалов и подтверждения назначенного владельца. Возврат DEFERRED / REJECTED / ACCEPTED к OPEN выполняется по условиям процесса; пересмотр сохраняет прежний выбор и его evidence, изменяет только подтверждённые затронутые зависимости.

## Кто заполняет строку

1. Manager ведёт реестр внутри `manager_artifact.md`, сохраняет IDs, назначает владельца решения и проверяет блокирующее влияние.
2. Роль передаёт Manager предложение новой DP или дополнение существующей: вопрос, контекст, пример, источники, варианты и подписанную рекомендацию.
3. Manager интегрирует вклад в одну запись, сохраняя авторство; параллельные предложения сверяются с актуальным baseline.
4. Выбор, основание и последствия фиксируются только по подтверждённому решению уполномоченного владельца.
5. Ролевой handoff ссылается на запись и её baseline. Подробные исходные findings и evidence остаются в ролевых материалах.

## Что содержит одна строка

| Колонка | Подробное содержание |
|---|---|
| ID | Новый ID имеет вид `DP-O-001`, `DP-A-001`, `DP-D-001` или `DP-T-001` и показывает происхождение вопроса. ID уникален в пределах change; ссылки из других change указывают также change ID. Существующие IDs сохраняются. |
| Автор / дата | Кто обнаружил вопрос и когда; рекомендации других ролей сохраняют своё авторство. |
| Статус и gate | `DecisionStatus`, этап или work item, который зависит от ответа, и допустимость независимого продолжения. |
| Вопрос, контекст и пример | Один однозначный вопрос; причина его появления; участники; конкретный сценарий, в котором варианты дают разное наблюдаемое поведение, стоимость или риск. |
| Источники | Связанные `FIND-*`, requirements, код, тесты, комментарии и ADR с проверенной версией. |
| Владелец и консультанты | Роль и имя владельца выбора; роли, чьё заключение требуется до решения. |
| Варианты и влияние | Для каждого реального варианта: что произойдёт, плюсы, минусы, влияние на пользователя, разработку, тестирование, эксплуатацию и обратимость. |
| Рекомендации ролей | Отдельно подписанная рекомендация каждой консультирующей роли с основанием. Пустое поле не трактуется как согласие. |
| Решение владельца | Выбранный вариант, однозначное правило поведения, обоснование, дата и роль владельца. До выбора указывается `не принято`. |
| Последствия и evidence | Польза, принятый риск, отложенная работа, обязательные обновления, ссылка на подтверждение и ADR при необходимости. |
| Возврат | Для отсрочки — ответственный, срок или событие пересмотра и влияние на следующий шаг. |
