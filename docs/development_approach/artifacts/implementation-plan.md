# Шаблон: план реализации

Файл: `docs/project_management/changes/<change-id>/plans/implementation_plan.md`. Пишет Developer в задаче review. «Структуру кода» проверяют до первой строки кода: в ALIGNMENT для фичи, Reviewer — для рефакторинга.

Правила:

- План помещается на два экрана. Детали шагов — в промтах `plans/prompts/<NN>-<тема>.md` по шаблону [prompt.md](prompt.md).
- «Структура кода» повторяет форму требований: таблица исходов в требованиях — таблица в коде, сценарий из стадий — функция на стадию.
- Промты нарезаны по проверяемому результату, а не по слоям. На каждую будет отдельная задача implement.
- Оценка — в чч и мч, с уверенностью и допущениями; сумма по промтам плюс ревью кода.
