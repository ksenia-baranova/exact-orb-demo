# Шаблон: промт для разработки

Файл: `docs/project_management/changes/<change-id>/plans/prompts/<NN>-<тема>.md`. Пишет Developer в задаче review вместе с [планом](implementation-plan.md).

Промт — задание на одну задачу implement. Её выполняет агент в новой сессии без переписки с тобой, поэтому всё нужное должно быть в промте.

Правила:

- Первые четыре строки — простым языком, без ID, SHA и путей. Если owner не поймёт их с первого чтения, перепиши.
- Промт помещается на один экран, примерно до 60 строк. Не помещается — это два промта.
- Один проверяемый результат на промт.
- Пиши, что сделать и как проверить, а не историю решений.

## Заготовка

```markdown
# Промт <NN>. <результат одной фразой>

**Проблема.** Что сейчас не так и у кого.
**Что делаем.** Что изменится после этого промта.
**Готово, когда.** Что можно увидеть или проверить.
**Не делаем.** Что остаётся за границей промта.

## Источники
- Требования: REQ-…, сценарии: AS-…
- Решения: DP-…, ADR-…
- Код: пути к модулям и тестам, которые меняются

## Структура
Какие функции и типы появляются или меняются, где таблица исходов, где логирование. Одна-две фразы на каждую часть.

## Шаги
1. Тесты: какие сценарии, на каких данных, что ожидаем. Подход: тест → код, код → тест или существующие тесты.
2. Код: что сделать.
3. Упрости: перечитай diff, убери лишнее, сверни дубли. Тесты публичного поведения не трогай.

## Проверки
- `pytest <целевые тесты>`
- `pytest <связанные тесты>`
- `pytest`
- `radon cc -s <изменённые модули>` — до и после

## Если упёрся
- Неясно ожидаемое поведение → DP для Analyst, задача с needs_decision.
- Не укладывается в промт или нужна перестройка чужого кода → DP для owner'а.
```

## Пример начала

```markdown
# Промт 05. Полное колесо карты без кликов

**Проблема.** На странице карты есть таблицы, но нет колеса — пользователь не видит карту целиком.
**Что делаем.** Рисуем полное колесо как картинку; выбор планет остаётся в таблицах. Подписи, которые не помещаются, выносим в колонку сбоку.
**Готово, когда.** Колесо и таблицы показывают одну и ту же карту; при ошибке рисования таблицы продолжают работать.
**Не делаем.** Не меняем HTTP, движок и эталонные данные.
```
