<a id="req-wheel-01"></a>
### REQ-WHEEL-01. Один опубликованный источник и заменяемое представление

**Основания:** DP-O-001, DP-O-010; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-01](scenarios.md#as-wheel-01), [AS-WHEEL-02](scenarios.md#as-wheel-02), [AS-WHEEL-22](scenarios.md#as-wheel-22), [AS-WHEEL-24](scenarios.md#as-wheel-24).

Колесо получает только ChartDTO, который прошёл действующую проверку ответа и принят страницей: committed POST либо chart_ready GET current. Одновременно показанные колесо, сводка и таблицы относятся к одной chart_identity. До принятого ChartDTO, включая bootstrap ready, декоративное колесо или демонстрационные факты не показываются. Renderer выполняет представление и сообщает о выборе; инициирование HTTP, управление сессией, разрешение birth input, engine/cache и изменение DTO не становятся его обязанностями. Наблюдаемый критерий заменяемости: альтернативный renderer принимает тот же подтверждённый набор фактов, воспроизводит семантику выбора и ошибок, подключается в пределах согласованной границы без изменения transport/session/расчёта. Точный интерфейс, владение выбором и граница замены ожидают DP-O-010; это критерий для консультации, а не выбранная структура модулей.

### REQ-WHEEL-02. Зодиак, позиции, дома и углы

**Основания:** DP-O-009, DP-O-011, DP-O-014; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-03](scenarios.md#as-wheel-03), [AS-WHEEL-04](scenarios.md#as-wheel-04), [AS-WHEEL-05](scenarios.md#as-wheel-05), [AS-WHEEL-07](scenarios.md#as-wheel-07), [AS-WHEEL-25](scenarios.md#as-wheel-25).

Положение истинной отметки и концов аспектов получается геометрическим переводом longitude / cusp_longitude; отображаемые знак, градусы, минуты, дом, retrograde, тип, категория и orb всегда берутся из DTO. Производные dsc/ic уже опубликованы projector; браузер не вычисляет их из asc/mc. Для natal ASC находится слева по его фактической опубликованной долготе, для cosmogram слева находится 0° Овна; в обоих режимах долготы возрастают против часовой стрелки — принятое DP-O-014. При разнесении символа сохраняются истинная отметка и однозначная связь с ней; точные правила условного смещения — REQ-WHEEL-05. Не создаются отсутствующие точки, линии или аспекты south_node. Конвенция ориентации принята, но геометрическая реализация, drawing ADR и независимые проверки ещё не выполнены.

<a id="req-wheel-04"></a>
### REQ-WHEEL-04. Состав аспектов и соединения

**Основания:** DP-O-006, DP-O-007, DP-O-008; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-06](scenarios.md#as-wheel-06), [AS-WHEEL-07](scenarios.md#as-wheel-07), [AS-WHEEL-08](scenarios.md#as-wheel-08), [AS-WHEEL-11](scenarios.md#as-wheel-11).

Без выбора аспекта графически представлены все и только опубликованные exact/working аспекты независимо от type. В режиме выбранного аспекта графический набор ограничен одной выбранной парой по REQ-WHEEL-07; сами points / angles карты не удаляются. Для остальных типов линия соединяет истинные долготы обоих endpoint IDs, разрешённых HTTP §7.2: points либо asc/mc/vertex. Аспект с углом не отбрасывается и не превращается в связь с ближайшей планетой; dsc/ic не добавляются в аспектную сетку. Для отображаемого conjunction есть различимый маркер ☌, связанный с конкретной опубликованной парой, и точная запись пары в HTML. Искусственное удлинение геометрии и повторный поиск аспектов не допускаются. Background остаётся только в полном табличном списке; при выборе показываются его два конца без линии и без маркера ☌. Если exact/working отсутствуют, колесо с точками остаётся видимым, а отсутствие графических аспектов явно отличимо от отсутствия карты. Переключателей категорий и новых фильтров типов нет.

<a id="req-wheel-05"></a>
### REQ-WHEEL-05. Скученность и ретроградность

**Основания:** DP-O-004, DP-O-005, DP-O-007, DP-O-011; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-09](scenarios.md#as-wheel-09), [AS-WHEEL-10](scenarios.md#as-wheel-10).

Каждая опубликованная точка различима, связана со своим каноническим ID и истинной отметкой. Retrograde=true имеет видимую R и доступную подпись на колесе и в HTML; false не получает R. По подтверждённой части DP-O-011 значки по умолчанию располагаются строго по долготам без разноса. Только при пересечении минимально смещаются конфликтующие элементы; неконфликтующие не смещаются. Выносная линия появляется только при фактическом смещении и однозначно ведёт к точной долготе; несмещённый символ её не получает. Порядок планет по долготе сохраняется, включая циклическую группу через 0°. При скученности несколько R и маркеров ☌ не подменяют соседние точки. Численный критерий пересечения / минимальности, направление смещения, алгоритм, пределы, размещение R / ☌ и fallback при невозможности полного разнесения остаются OPEN в DP-O-011. AS-WHEEL-09/10 задают проверочные наборы, а не числа spread() прототипа. Приоритет компактности сохраняется; скрытие фактов без принятого решения недопустимо.

<a id="req-wheel-06"></a>
### REQ-WHEEL-06. Различение категорий и типов

**Основания:** DP-O-012; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-08](scenarios.md#as-wheel-08).

Для линий опубликованных exact / working аспектов категории различаются рисунком: exact — сплошная линия, working — пунктирная. Вид аспекта различается цветом и текстовым пояснением в легенде / HTML таблице; штрих не получает второго значения типа. Выбранный линейный аспект выделяется более толстой линией, сохраняя его цвет и сплошной / пунктирный рисунок. Тип, категория, пара и опубликованный orb доступны текстом, поэтому понимание не зависит только от цвета. Легенда соответствует фактической графике. Для ☌ Owner выбрал подпись «точный» / «рабочий» рядом с символом и усиленный контур только вокруг выбранного символа; общая рамка символа с подписью не используется, подпись категории сохраняется при выборе. Это отдельное правило маркера, а не штрих обычной хорды. Конкретная палитра, оформление легенды, размещение нескольких ☌, интервалы и численная толщина контура остаются OPEN в DP-O-011/012; цвета и геометрия визуального эскиза не утверждены. Background не получает линии или ☌ даже после выбора. Пороги категорий и значения orb не меняются.

<a id="req-wheel-07"></a>
### REQ-WHEEL-07. Двусторонний выбор

**Основания:** DP-O-008, DP-O-010, DP-O-013; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-27](scenarios.md#as-wheel-27), [AS-WHEEL-11](scenarios.md#as-wheel-11), [AS-WHEEL-12](scenarios.md#as-wheel-12), [AS-WHEEL-13](scenarios.md#as-wheel-13). [AS-WHEEL-28](scenarios.md#as-wheel-28).

В каждый момент выбран либо один point, либо один опубликованный аспект, либо ничего. Выбор планеты и выбор аспекта взаимоисключающие; подсветка двух концов выбранного аспекта не является выбором планеты. Активация point на колесе и его строки points выбирает один канонический ID; другая планета заменяет прежнюю, а после выбранного аспекта переводит UI в режим планеты. Самостоятельный выбор углов / домов не добавляется.

При выборе планеты таблица aspects показывает все её опубликованные аспекты с остальной картой, включая background и разрешённые HTTP angle endpoints, сразу без лимита пяти. Фильтр сверяет from/to по ID, сохраняет порядок DTO и не рассчитывает новые пары. Пустой отбор явно отличим от отсутствия аспектов у всей карты. При выборе планеты таблица обновляется на месте без автоматической прокрутки страницы и программного переноса фокуса. Дословное Owner «с другими планетами» не является решением исключить опубликованные points / angles из DTO.

Активация любого опубликованного аспекта с колеса либо из HTML снимает выбор планеты и её отбор. Таблица aspects содержит ровно одну выбранную строку, а из графических аспектов остаётся только обозначение этой пары; обе стороны действуют одинаково, в том числе при выборе аспекта вне прежнего фильтра планеты. Для exact/working подсвечиваются оба опубликованных конца и выбранная линия / ☌; для background показываются только два конца, без линии и без ☌, остальные графические аспекты скрыты. Положения всех объектов карты сохраняются. Выбор одной строки не изменяет DTO; после снятия доступен общий список по REQ-WHEEL-08. Никакой интерпретации / LLM-вызова или нового блока её генерации это действие не добавляет: Owner назвал будущую интерпретацию только мотивом выбора одной пары.

Размещение совпадающих маркеров, mobile hit targets и конкретный порядок keyboard navigation ещё требуют Developer / Tester input в DP-O-011/013. Техническое владение состоянием / интерфейс renderer остаются DP-O-010.

<a id="req-wheel-08"></a>
### REQ-WHEEL-08. Снятие и принадлежность выбора карте

**Основания:** DP-O-008, DP-O-013; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-13](scenarios.md#as-wheel-13), [AS-WHEEL-14](scenarios.md#as-wheel-14), [AS-WHEEL-15](scenarios.md#as-wheel-15), [AS-WHEEL-17](scenarios.md#as-wheel-17), [AS-WHEEL-18](scenarios.md#as-wheel-18). [AS-WHEEL-29](scenarios.md#as-wheel-29), [AS-WHEEL-30](scenarios.md#as-wheel-30).

Повторная активация выбранной планеты снимает её выбор / подсветку и отбор aspects: сразу видны первые пять общего списка с отдельной кнопкой «Показать все». Это прежнее принятое правило не заменяется правилом снятия аспекта. Отдельная кнопка «Снять выделение» не добавляется.

Повторная активация выбранного аспекта через его линию, ☌ либо строку снимает выбор. То же действие доступно с клавиатуры. Возвращаются обычный графический набор exact/working и общий список aspects с прежним состоянием его раскрытия: первые пять либо все. Прежний планетный фильтр не восстанавливается. Сохранённое раскрытие относится к обычному списку, а не к единственной строке выбранного аспекта; houses от этого действия не меняются.

При полной перезагрузке F5/«Обновить» выбор / подсветка и раскрытие таблиц сбрасываются; восстановленный current рисует карту заново с первыми пятью aspects / houses. Отдельно сохраняется reset при принятии новой карты после успешного явного build по изменённым birth data. Изменение полей, отказ build и неопределённый исход сами по себе не заменяют принятую карту и не являются этим событием reset. При resize выбор и раскрытие сохраняются, HTTP нет.

Автоматическое чтение при возвращении видимой вкладки / online само по себе не сбрасывает выбор и раскрытие. Отдельное событие принятия нового результата собственного явного build по изменённым birth data сохраняет правило reset выше; оно не определяется одним лишь HTTP-методом источника ответа. При chart_ready с той же или другой identity сохраняется только выбор, адресуемый опубликованным объектом / аспектом нового ответа; показываются его новые факты. Если выбранный объект / аспект отсутствует, снимается только этот исчезнувший выбор, раскрытие таблиц сохраняется. Это прямо подтверждённое Owner исключение; полный reset при любом отличии identity не вводится. Например, natal moon→asc не переносится на cosmogram без angles. При снятии исчезнувшего выбора действует общий список с сохранённым раскрытием, а не старые данные / вымышленная пара. Ошибка чтения не доказывает исчезновение выбранной записи. Подтверждённые empty / unavailable убирают колесо и выбор по действующему контракту; старые числовые факты не переносятся на состояние без ChartDTO.

<a id="req-wheel-09"></a>
### REQ-WHEEL-09. Композиция и адаптивность

**Основания:** DP-O-001, DP-O-002, DP-O-003, DP-O-011, DP-O-013; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-26](scenarios.md#as-wheel-26), [AS-WHEEL-01](scenarios.md#as-wheel-01), [AS-WHEEL-02](scenarios.md#as-wheel-02), [AS-WHEEL-16](scenarios.md#as-wheel-16).

Колесо появляется сразу после принятого committed / current ChartDTO и не зависит от раскрытия подробностей. На desktop оно справа от краткой сводки рождения, при сужении может перейти под сводку, на mobile находится под сводкой. Таблицы aspects и рассчитанных houses также доступны сразу: обычный вид показывает первые пять строк каждой в существующем порядке, у каждой таблицы своя кнопка «Показать все» для остальных строк. Для домов порядок number=1…12, для аспектов — порядок DTO; ранжирование не меняется. При выборе планеты все её опубликованные аспекты видны сразу без лимита пяти. Null houses cosmogram не превращается в пять вымышленных строк. Все опубликованные положения points показываются сразу без лимита пяти. Опубликованные angles, включая Vertex, представлены отдельным компактным табличным блоком; отсутствующие углы не синтезируются, в cosmogram такого блока нет. Это композиция существующих фактов, без самостоятельного выбора углов. Точное место блока / перестановка его строк отдельно не утверждены; три прежние расчётные группы не расширяются новой публичной группой. При выбранном аспекте его таблица содержит одну строку по REQ-WHEEL-07. Старое глобальное раскрытие подробностей не может скрывать сразу видимые facts.

На 360 px страница без горизонтального переполнения; знаки, точки, R и ☌ различимы, полные факты доступны в HTML. Контрольные ширины — 1440, 768, 360 px; breakpoint / радиусы Analyst не назначает. Resize сохраняет выбранную планету и раскрытие таблиц, не меняет данные и не отправляет запросов.

<a id="req-ui-04"></a>
### REQ-UI-04. Представление общих фактов

**Операция:** MODIFY. **Исходный пункт:** REQ-UI-04 @ MainBaseline. **Целевой пункт:** тот же ID в `current/ui/birth-form-and-facts.md`.
**Основания:** DP-O-005. **Добавочные сценарии:** [AS-WHEEL-03](scenarios.md#as-wheel-03), [AS-WHEEL-09](scenarios.md#as-wheel-09), [AS-WHEEL-16](scenarios.md#as-wheel-16).

**Сценарии:** [AS-UI-07–09, 15, 22](../../../../requirements/current/ui/scenarios.md).
- Три группы имеют самостоятельные заголовки и доступные таблицы/списки. Видимый порядок внутри группы детерминирован; локализованные подписи привязаны к стабильным кодам DTO. Позиции показывают опубликованные `sign`, целые `degree` и `minute` как `ДД°ММ′` (минута всегда двумя цифрами, без секунд и длинной дроби). Край знака берётся из опубликованного `sign`, а не из вычисления браузера. `retrograde=true` обозначается видимой `R` с доступной подписью «ретроградная»; `false` не получает `R`.
- Публикуемый `orb` форматируется как ближайшая целая угловая минута: округлить `orb × 60` до целого, при точной половине минуты — вверх, затем вывести градусы и двухзначные минуты `D°ММ′`. Например, `0.008°` → `0°00′`, `0.009°` → `0°01′`, `0.999°` → `1°00′`, `1.5°` → `1°30′`. Это только экранное округление; `orb`, `type` и `category` в `ChartDTO` не изменяются, а категория не выводится из округлённого текста. Такое же ближайшее округление уже использует CLI `_format_orb` для обычных не-граничных значений; правило точной половины фиксируется для проверяемого UI.
- Для доступного рассчитанного списка `[]` означает «рассчитано, результатов нет»; `null` означает «не применимо» и не изображается пустым рассчитанным результатом. У космограммы `houses:null`, а `aspects:[]` означает отсутствие устойчивых аспектов. Для `chart_unavailable` нет `ChartDTO`; показывается отказ восстановления, а не три пустые таблицы.
- Наличие сырых `longitude`/`cusp_longitude` в нынешнем DTO не даёт права получать из них табличные градусы/минуты. `degree_in_sign` в публичном DTO уже отсутствует. Числовые демонстрационные значения не подставляются вместо ответа API.

**Добавка M1-8:** Во всех строках retrograde=true имеет видимую R с доступной подписью; табличные позиции / orb не зависят от разноса символов. Все points видны сразу, angles представлены отдельным компактным табличным блоком. Общий список aspects / natal houses первоначально содержит первые пять строк и независимые «Показать все». ### REQ-UI-09. Recovery и две вкладки

**Операция:** MODIFY. **Исходный пункт:** REQ-UI-09 @ MainBaseline. **Целевой пункт:** тот же ID в `current/ui/birth-form-and-facts.md`.
**Основания:** DP-O-003/008/010/013. **Добавочные сценарии:** [AS-WHEEL-17](scenarios.md#as-wheel-17), [AS-WHEEL-18](scenarios.md#as-wheel-18), [AS-WHEEL-19](scenarios.md#as-wheel-19), [AS-WHEEL-20](scenarios.md#as-wheel-20), [AS-WHEEL-21](scenarios.md#as-wheel-21), [AS-WHEEL-22](scenarios.md#as-wheel-22).

**Сценарии:** [AS-UI-12](../../../../requirements/current/ui/scenarios.md#as-ui-12-утерянная-сессия-и-сохранение-черновика), [AS-UI-13](../../../../requirements/current/ui/scenarios.md#as-ui-13-rate-и-capacity-до-запуска-build), [AS-UI-14](../../../../requirements/current/ui/scenarios.md#as-ui-14-неопределённый-исход-commit-и-timeout), [AS-UI-16](../../../../requirements/current/ui/scenarios.md#as-ui-16-две-вкладки-и-superseded), [AS-UI-18](../../../../requirements/current/ui/scenarios.md#as-ui-18-пустой-поиск-и-отказ-каталога), [AS-UI-23](../../../../requirements/current/ui/scenarios.md#as-ui-23-потерян-ответ-build).

При отказе клиент сохраняет черновик даты, времени/отметки и подтверждённого выбора места в текущей вкладке. Ответ определяет следующий запрос и показанное состояние:

| Полученный ответ | Следующий запрос клиента | Состояние экрана и действие пользователя |
|---|---|---|
| `409 SESSION_REQUIRED/EXPIRED/NOT_FOUND` | `POST /session/bootstrap {}` → `GET /charts/current`. | Показать действительное состояние новой/восстановленной сессии и сохранить черновик; новый build только по явному действию. |
| `409 RESULT_SUPERSEDED` или `200 already_applied` | `GET /charts/current`. | Показать фактическую карту из GET; не выдавать ответ POST за новую карту. |
| `429` или pre-admission `503 BUILD_CAPACITY_EXHAUSTED` | Автоматического повторного POST нет. | Показать `Retry-After`; после него предложить пользователю явное повторное действие. |
| `503 STATE_READ_FAILED` | Повторить безопасное чтение после восстановления доступности; cookie сохраняется. | Сохранить форму и сообщить о временной невозможности чтения. |
| `503 STATE_COMMIT_FAILED` | После `Retry-After` выполнить только `GET /charts/current`. | Исход build пока неопределён; показать результат сверки, не повторять POST автоматически. |
| `504 BUILD_TIMEOUT` | После `Retry-After` и подтверждённого restart/readiness выполнить bootstrap → current. | До сверки не объявлять build ни успешным, ни неуспешным и не отправлять POST автоматически. |
| Ответ POST потерян из-за обрыва соединения, сетевой ошибки или закрытия вкладки; HTTP status и `ErrorDTO` неизвестны | После возвращения связи выполнить только bootstrap → current. Отсутствующий `Retry-After` не выдумывать. | Сохранить доступный черновик. До сверки сообщить: «Не удалось получить ответ о построении карты. Проверяем текущую карту». Если current содержит карту исходного намерения, показать её; если карта другая, показать актуальную карту и сохранить черновик. Если current показывает старую/пустую карту, показать «Что-то пошло не так. Новый результат пока не появился. Введённые данные сохранены. Вы можете построить карту ещё раз; предыдущий расчёт может завершиться позже» и активное «Построить ещё раз». Если bootstrap/current не удался, оставить исход неопределённым и предложить повторить только безопасную проверку карты. |

Если после подтверждённого restart GET возвращает `empty` или старую карту, новый POST возможен только по явному действию. При потере ответа владелец выбрал вариант B: после **успешного** bootstrap → current со старой/пустой картой новый POST разрешён только по отдельному нажатию «Построить ещё раз» при действующей ручной отметке ADR-0034, без повторного ввода даты, времени и места. Если вкладка открылась заново и отметка сброшена, пользователь ставит её вручную. Такой GET не доказывает завершение первого build; UI не утверждает, что расчёт не удался, и после повторного POST показывает только фактический committed результат либо снова сверяет current по полученному outcome. Пока bootstrap/current не ответил успешно, повтор build недоступен. Когда вкладка B явно построила карту, возврат вкладки A выполняет bootstrap → current и показывает сохранённую B карту; локальный `state_version` A не является серверным expected version. Решение владельца зарегистрировано в DP-UI-09 @ `64934fc`; контракт повторно сверён Tester @ `0f6aa82`, утверждение Manager для реализации — в связанном Change Plan.

**Добавка M1-8:** Последняя подтверждённая карта с колесом / сводкой может оставаться при отказе чтения / build с ясным состоянием проверки; подтверждённый empty/unavailable удаляет числовое представление. Recovery intent, локальный draft и actual current различимы. При automatic chart_ready открытая форма сохраняет несохранённый draft; сводка / колесо / HTML показывают факты принятого ответа. Выбор / раскрытие подчиняются REQ-WHEEL-08, включая снятие только исчезнувшего выбора. Сообщения, Retry-After/restart gate, safe recheck и разрешённый ручной повтор доступны при свёрнутом редакторе; их техническое расположение / focus ещё требует review DP-O-013. Поздний ответ / dispose сохраняют baseline guards.

### REQ-UI-11. Сводка показанной карты и раскрытие формы

**Операция:** ADD. **Исходный пункт:** отсутствует; связаны REQ-UI-01/03/08/09 @ MainBaseline. **Целевой пункт:** `docs/requirements/current/ui/birth-form-and-facts.md#req-ui-11`.

Сохранение несохранённого draft сквозь F5 / закрытие вкладки не требуется.
