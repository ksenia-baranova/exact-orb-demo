<a id="req-wheel-01"></a>
### REQ-WHEEL-01. Один опубликованный источник и заменяемое представление

**Основания:** DP-O-001, DP-O-010; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-01](scenarios.md#as-wheel-01), [AS-WHEEL-02](scenarios.md#as-wheel-02), [AS-WHEEL-22](scenarios.md#as-wheel-22), [AS-WHEEL-24](scenarios.md#as-wheel-24).

Колесо получает только ChartDTO, который прошёл действующую проверку ответа и принят страницей: committed POST либо chart_ready GET current. Одновременно показанные колесо, сводка и таблицы относятся к одной chart_identity. До принятого ChartDTO, включая bootstrap ready, декоративное колесо или демонстрационные факты не показываются. Renderer выполняет представление и сообщает о выборе; инициирование HTTP, управление сессией, разрешение birth input, engine/cache и изменение DTO не становятся его обязанностями. Наблюдаемый критерий заменяемости: альтернативный renderer принимает тот же подтверждённый набор фактов, воспроизводит семантику выбора и ошибок, подключается в пределах согласованной границы без изменения transport/session/расчёта. Точный интерфейс, владение выбором и граница замены ожидают DP-O-010; это критерий для консультации, а не выбранная структура модулей.

<a id="req-wheel-02"></a>
### REQ-WHEEL-02. Зодиак, позиции, дома и углы

**Основания:** DP-O-009, DP-O-011, DP-O-014; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-03](scenarios.md#as-wheel-03), [AS-WHEEL-04](scenarios.md#as-wheel-04), [AS-WHEEL-05](scenarios.md#as-wheel-05), [AS-WHEEL-07](scenarios.md#as-wheel-07), [AS-WHEEL-25](scenarios.md#as-wheel-25).

SVG содержит кольцо двенадцати знаков в каноническом порядке, опубликованные points, а для natal — двенадцать опубликованных куспидов и пять подписанных angles: asc, mc, vertex, dsc, ic. Положение истинной отметки и концов аспектов получается геометрическим переводом longitude / cusp_longitude; отображаемые знак, градусы, минуты, дом, retrograde, тип, категория и orb всегда берутся из DTO. Производные dsc/ic уже опубликованы projector; браузер не вычисляет их из asc/mc. Для natal ASC находится слева по его фактической опубликованной долготе, для cosmogram слева находится 0° Овна; в обоих режимах долготы возрастают против часовой стрелки — принятое DP-O-014. При разнесении символа сохраняются истинная отметка и однозначная связь с ней; точные правила условного смещения — REQ-WHEEL-05. Не создаются отсутствующие точки, линии или аспекты south_node. Конвенция ориентации принята, но геометрическая реализация, drawing ADR и независимые проверки ещё не выполнены.

<a id="req-wheel-03"></a>
### REQ-WHEEL-03. Космограмма

**Основания:** DP-O-009; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-05](scenarios.md#as-wheel-05), [AS-WHEEL-06](scenarios.md#as-wheel-06).

Для kind=cosmogram 0° Овна находится слева, долготы возрастают против часовой стрелки по DP-O-009/014. Отсутствуют дома, углы, ASC и любые данные времени технического якоря вместо неизвестного рождения. Показываются опубликованные points и только аспекты из ответа; пустой aspects не восстанавливается локальным расчётом. Видны пояснения baseline о техническом якоре позиций и консервативном максимальном orb устойчивых аспектов. Диапазон Луны, time_dependent, обещание точного момента и предупреждения прототипа не синтезируются.

<a id="req-wheel-04"></a>
### REQ-WHEEL-04. Состав аспектов и соединения

**Основания:** DP-O-006, DP-O-007, DP-O-008; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-06](scenarios.md#as-wheel-06), [AS-WHEEL-07](scenarios.md#as-wheel-07), [AS-WHEEL-08](scenarios.md#as-wheel-08), [AS-WHEEL-11](scenarios.md#as-wheel-11).

Графически представлены все и только опубликованные exact/working аспекты независимо от type. Для остальных типов линия соединяет истинные долготы обоих endpoint IDs, разрешённых HTTP §7.2: points либо asc/mc/vertex. Аспект с углом не отбрасывается и не превращается в связь с ближайшей планетой; dsc/ic не добавляются в аспектную сетку. Для отображаемого conjunction есть различимый маркер ☌, связанный с конкретной опубликованной парой, и точная запись пары в HTML. Искусственное удлинение геометрии и повторный поиск аспектов не допускаются. Background остаётся только в полном табличном списке; при выборе показываются его два конца без линии и без маркера ☌. Если exact/working отсутствуют, колесо с точками остаётся видимым, а отсутствие графических аспектов явно отличимо от отсутствия карты. Переключателей категорий и новых фильтров типов нет.

<a id="req-wheel-05"></a>
### REQ-WHEEL-05. Скученность и ретроградность

**Основания:** DP-O-004, DP-O-005, DP-O-007, DP-O-011; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-09](scenarios.md#as-wheel-09), [AS-WHEEL-10](scenarios.md#as-wheel-10).

Каждая опубликованная точка различима, связана со своим каноническим ID и истинной отметкой. Retrograde=true имеет видимую R и доступную подпись на колесе и в HTML; false не получает R. По подтверждённой части DP-O-011 значки по умолчанию располагаются строго по долготам без разноса. Только при пересечении минимально смещаются конфликтующие элементы; неконфликтующие не смещаются. Выносная линия появляется только при фактическом смещении и однозначно ведёт к точной долготе; несмещённый символ её не получает. Порядок планет по долготе сохраняется, включая циклическую группу через 0°. При скученности несколько R и маркеров ☌ не подменяют соседние точки. Численный критерий пересечения / минимальности, направление смещения, алгоритм, пределы, размещение R / ☌ и fallback при невозможности полного разнесения остаются OPEN в DP-O-011. AS-WHEEL-09/10 задают проверочные наборы, а не числа spread() прототипа. Приоритет компактности сохраняется; скрытие фактов без принятого решения недопустимо.

<a id="req-wheel-06"></a>
### REQ-WHEEL-06. Различение категорий и типов

**Основания:** DP-O-012; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-08](scenarios.md#as-wheel-08).

Для линий опубликованных exact / working аспектов категории различаются рисунком: exact — сплошная линия, working — пунктирная. Вид аспекта различается цветом и текстовым пояснением в легенде / HTML таблице; штрих не получает второго значения типа. Выбранный линейный аспект выделяется более толстой линией, сохраняя его цвет и сплошной / пунктирный рисунок. Тип, категория, пара и опубликованный orb доступны текстом, поэтому понимание не зависит только от цвета. Легенда соответствует фактической графике. Конкретная палитра, оформление легенды и отображение категории / выбора для маркера ☌ пока OPEN в DP-O-012: правило сплошной / пунктирной линии не заменяет нерешённое оформление маркера. Background не получает линии или ☌ даже после выбора. Пороги категорий и значения orb не меняются.

<a id="req-wheel-07"></a>
### REQ-WHEEL-07. Двусторонний выбор

**Основания:** DP-O-008, DP-O-010, DP-O-013; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-27](scenarios.md#as-wheel-27), [AS-WHEEL-11](scenarios.md#as-wheel-11), [AS-WHEEL-12](scenarios.md#as-wheel-12), [AS-WHEEL-13](scenarios.md#as-wheel-13).

Активация point на колесе связывает его с соответствующей строкой points; активация строки points выбирает тот же канонический ID на колесе. При выборе одной планеты таблица aspects показывает все её опубликованные аспекты с остальной картой, включая background, сразу без лимита пяти. Выбор другой планеты заменяет прежнюю; множественный выбор планет не входит в принятый вариант. Повторная активация выбранной планеты снимает выбор и отбор; обычный список возвращается к первым пяти аспектам и своей кнопке «Показать все». Отбор сохраняет исходный порядок DTO и проверяет from/to по ID, не рассчитывает новые аспекты. Если совпадающих записей нет, виден понятный пустой результат отбора; это не сообщение об отсутствии аспектов у всей карты. При выборе планеты таблица обновляется на месте без автоматической прокрутки страницы и программного переноса фокуса. Самостоятельный выбор углов / домов не добавляется.

Активация графического exact / working аспекта связывает его с конкретной строкой aspects и его двумя концами. Выбор строки aspects выделяет оба конца и графическое обозначение только для exact / working. Background выделяет два опубликованных конца, включая angle, без линии / ☌. Это не меняет числовые факты. Взаимодействие выбора аспекта с активным отбором по планете, способ снятия выбора аспекта, доступность совпадающих маркеров, мобильные hit targets и порядок keyboard navigation ещё требуют DP-O-013; выбор планеты / его снятие уже определены и не считаются условными.

<a id="req-wheel-08"></a>
### REQ-WHEEL-08. Снятие и принадлежность выбора карте

**Основания:** DP-O-008, DP-O-013; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-13](scenarios.md#as-wheel-13), [AS-WHEEL-14](scenarios.md#as-wheel-14), [AS-WHEEL-15](scenarios.md#as-wheel-15), [AS-WHEEL-17](scenarios.md#as-wheel-17), [AS-WHEEL-18](scenarios.md#as-wheel-18).

Выбор планеты снимается повторной активацией той же планеты, в том числе с клавиатуры; отдельная кнопка «Снять выделение» не добавляется по решению Owner. После снятия оба представления не отмечают прежний выбор, отбор aspects снят и видны первые пять общего списка с отдельной кнопкой «Показать все». При принятии новой карты после успешного явного построения по изменённым данным рождения сбрасываются выбор планеты / аспекта, подсветка и раскрытие таблиц; рисуется новое колесо, аспекты и дома возвращаются к первым пяти строкам с отдельными кнопками. Изменение полей без принятого нового результата, отказ build и неопределённый исход не заменяют показанную карту этим событием. Старый выбор никогда не адресует запись другой chart_identity.

При resize сохраняются выбранная планета и раскрытие таблиц; опубликованные данные не меняются, сетевой запрос не выполняется. Подтверждённые empty / unavailable убирают колесо и выбор. Политика сохранения состояния при повторном current той же карты, самостоятельное снятие выбора аспекта и иные нерешённые переходы остаются OPEN в DP-O-013; сохранение при resize не переносится на них автоматически.

<a id="req-wheel-09"></a>
### REQ-WHEEL-09. Композиция и адаптивность

**Основания:** DP-O-001, DP-O-002, DP-O-003, DP-O-011, DP-O-013; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-26](scenarios.md#as-wheel-26), [AS-WHEEL-01](scenarios.md#as-wheel-01), [AS-WHEEL-02](scenarios.md#as-wheel-02), [AS-WHEEL-16](scenarios.md#as-wheel-16).

Колесо появляется сразу после принятого committed / current ChartDTO и не зависит от раскрытия подробностей. На desktop оно справа от краткой сводки рождения, при сужении может перейти под сводку, на mobile находится под сводкой. Таблицы aspects и рассчитанных houses также доступны сразу: обычный вид показывает первые пять строк каждой в существующем порядке, у каждой таблицы своя кнопка «Показать все» для остальных строк. Для домов порядок number=1…12, для аспектов — порядок DTO; ранжирование не меняется. При выборе планеты все её опубликованные аспекты видны сразу без лимита пяти. Null houses cosmogram не превращается в пять вымышленных строк. Композиция points / angles и остальные interaction-вопросы требуют DP-O-013; старое глобальное раскрытие подробностей не может скрывать принятые сразу видимые аспекты / дома.

На 360 px страница без горизонтального переполнения; знаки, точки, R и ☌ различимы, полные факты доступны в HTML. Контрольные ширины — 1440, 768, 360 px; breakpoint / радиусы Analyst не назначает. Resize сохраняет выбранную планету и раскрытие таблиц, не меняет данные и не отправляет запросов.

<a id="req-wheel-10"></a>
### REQ-WHEEL-10. Доступное управление и честный отказ изображения

**Основания:** DP-O-008, DP-O-010, DP-O-011, DP-O-012, DP-O-013; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-16](scenarios.md#as-wheel-16), [AS-WHEEL-23](scenarios.md#as-wheel-23), [AS-WHEEL-24](scenarios.md#as-wheel-24).

Колесо имеет текстовое название / описание; канонические объекты и соответствующие строки доступны без hover. Пользователь с клавиатуры может выбрать планету, снять её выбор повторной активацией, выбрать доступный аспект и раскрыть остальные строки каждой таблицы; focus видим. Выбор планеты не прокручивает страницу и не переносит focus программно. Отдельной кнопки «Снять выделение» нет; конкретные порядок клавиатурной навигации, мобильные hit targets и снятие выбора аспекта ещё требуют DP-O-013. Категория линии читается по сплошному / пунктирному рисунку, вид — по цвету и тексту; визуальный эффект не опирается только на цвет.

Подтверждённая часть DP-O-010 требует локального отказа: если колесо не удалось отрисовать, таблицы и подтверждённые данные той же принятой карты остаются доступны, пользователь видит сообщение об ошибке колеса. Отказ SVG не выдаётся за отсутствие ChartDTO, ошибку расчёта или успешный показ колеса; данные разных карт не смешиваются. Сам отказ изображения не запускает build и не уничтожает опубликованные HTML факты. Техническая изоляция отказа / повтор отображения, точная граница renderer и прочие части DP-O-010 ещё открыты. Действующие safe-read / Retry-After / restart gates при HTTP recovery сохраняются.

### REQ-UI-04. Представление общих фактов

**Операция:** MODIFY. **Исходный пункт:** REQ-UI-04 @ MainBaseline. **Целевой пункт:** тот же ID в `current/ui/birth-form-and-facts.md`.
**Основания:** DP-O-005. **Добавочные сценарии:** [AS-WHEEL-03](scenarios.md#as-wheel-03), [AS-WHEEL-09](scenarios.md#as-wheel-09), [AS-WHEEL-16](scenarios.md#as-wheel-16).

**Сценарии:** [AS-UI-07–09, 15, 22](../../../../requirements/current/ui/scenarios.md).
- Три группы имеют самостоятельные заголовки и доступные таблицы/списки. Видимый порядок внутри группы детерминирован; локализованные подписи привязаны к стабильным кодам DTO. Позиции показывают опубликованные `sign`, целые `degree` и `minute` как `ДД°ММ′` (минута всегда двумя цифрами, без секунд и длинной дроби). Край знака берётся из опубликованного `sign`, а не из вычисления браузера. `retrograde=true` обозначается видимой `R` с доступной подписью «ретроградная»; `false` не получает `R`.
- Публикуемый `orb` форматируется как ближайшая целая угловая минута: округлить `orb × 60` до целого, при точной половине минуты — вверх, затем вывести градусы и двухзначные минуты `D°ММ′`. Например, `0.008°` → `0°00′`, `0.009°` → `0°01′`, `0.999°` → `1°00′`, `1.5°` → `1°30′`. Это только экранное округление; `orb`, `type` и `category` в `ChartDTO` не изменяются, а категория не выводится из округлённого текста. Такое же ближайшее округление уже использует CLI `_format_orb` для обычных не-граничных значений; правило точной половины фиксируется для проверяемого UI.
- Для доступного рассчитанного списка `[]` означает «рассчитано, результатов нет»; `null` означает «не применимо» и не изображается пустым рассчитанным результатом. У космограммы `houses:null`, а `aspects:[]` означает отсутствие устойчивых аспектов. Для `chart_unavailable` нет `ChartDTO`; показывается отказ восстановления, а не три пустые таблицы.
- Наличие сырых `longitude`/`cusp_longitude` в нынешнем DTO не даёт права получать из них табличные градусы/минуты. `degree_in_sign` в публичном DTO уже отсутствует. Числовые демонстрационные значения не подставляются вместо ответа API.

**Добавка M1-8:** Во всех строках retrograde=true имеет видимую R с доступной подписью, false не получает R; табличные позиции / orb не зависят от разноса символов. Таблицы aspects / houses доступны сразу с первыми пятью строками и отдельной кнопкой «Показать все» у каждой; ограничение не меняет полный опубликованный набор. При выборе планеты видны все её аспекты без лимита; при снятии возвращаются первые пять общего списка. Новая принятая карта по изменённым birth data сбрасывает выделение / раскрытие, resize сохраняет выбранную планету / раскрытие. Композиция остальных facts / angles ещё открыта.

Все аспекты доступны в порядке DTO: обычный вид показывает первые пять строк со своей кнопкой «Показать все», выбор планеты — все её опубликованные аспекты сразу без лимита пяти. Пустой полный список показывает «Аспекты не найдены». Для космограммы показываются только устойчивые опубликованные аспекты ADR-0032; `orb` означает максимальное значение по допустимым минутам, а не точный орбис полудня. UI не синтезирует `time_dependent` и не восстанавливает исключённые пары.

**Добавка M1-8:** Колесо представляет только exact/working; HTML сохраняет все опубликованные категории и исходный порядок. В обычном виде таблица aspects доступна сразу, показывает первые пять записей и свою кнопку «Показать все» для остальных. Выбор одной планеты показывает все её опубликованные аспекты сразу без лимита пяти; другая заменяет выбор, повтор той же снимает его и возвращает первые пять общего списка / «Показать все». Нет автопрокрутки или переноса focus. Пустой отбор отличается от пустого списка всей карты. From/to могут адресовать angles; background остаётся без линии / ☌. Категории линий exact/working — сплошная/пунктирная, типы — цвет + текст, выбор — толще с сохранением рисунка/цвета; остальные части DP-O-012/013 открыты.

### REQ-UI-08. Восстановление, stale и unavailable

**Операция:** MODIFY. **Исходный пункт:** REQ-UI-08 @ MainBaseline. **Целевой пункт:** тот же ID в `current/ui/birth-form-and-facts.md`.
**Основания:** DP-O-001/003/009. **Добавочные сценарии:** [AS-WHEEL-02](scenarios.md#as-wheel-02), [AS-WHEEL-05](scenarios.md#as-wheel-05), [AS-WHEEL-15](scenarios.md#as-wheel-15), [AS-WHEEL-17](scenarios.md#as-wheel-17).

**Сценарии:** [AS-UI-10](../../../../requirements/current/ui/scenarios.md#as-ui-10-восстановление-без-расчёта), [AS-UI-11](../../../../requirements/current/ui/scenarios.md#as-ui-11-устаревшая-и-недоступная-сохранённая-карта), [AS-UI-12](../../../../requirements/current/ui/scenarios.md#as-ui-12-утерянная-сессия-и-сохранение-черновика).

**Пользовательское действие:** перезагрузить страницу с живой cookie или вернуться к ней. Клиент выполняет шаги bootstrap → current из REQ-UI-01. Чтение не запускает расчёт и не меняет сохранённую карту.

| Ответ `GET /charts/current` | Состояние экрана | Следующее действие |
|---|---|---|
| `chart_ready`, `chart_stale:false` | Те же `chart_identity`, сохранённый `birth` и факты трёх групп, что были в committed POST. | Не требуется. |
| `chart_ready`, `chart_stale:true` | Старая карта и её факты сохранены, версия явно помечена как устаревшая. Текущая версия расчёта не подменяет числа автоматически. | Пользователь может явно нажать «Пересчитать». |
| `chart_unavailable`, `chart:null` | Сохранённый `birth` виден; числовые факты и три таблицы не показаны. | Пользователь может явно нажать «Построить заново». |

Если восстановленный `birth.time_unknown=true`, в нём `birth_time:null`, `utc_offset_seconds:null`: UI может назвать `tz_id`, но не показывает offset технического полудня или выдуманный диапазон Луны.

**Добавка M1-8:** Для chart_ready колесо соответствует исходному сохранённому ChartDTO, включая stale; отметка устаревания видна вместе с ним. Chart_unavailable показывает birth и доступное явное построение, без колеса; empty убирает колесо и прежнюю сводку карты. Смена identity не переносит на новую карту чужое выделение. Действия восстановления и данные baseline сохраняются.

<a id="req-ui-09"></a>
### REQ-UI-09. Recovery и две вкладки

**Операция:** MODIFY. **Исходный пункт:** REQ-UI-09 @ MainBaseline. **Целевой пункт:** тот же ID в `current/ui/birth-form-and-facts.md`.
**Основания:** DP-O-003/008/010/013. **Добавочные сценарии:** [AS-WHEEL-17](scenarios.md#as-wheel-17), [AS-WHEEL-18](scenarios.md#as-wheel-18), [AS-WHEEL-19](scenarios.md#as-wheel-19), [AS-WHEEL-20](scenarios.md#as-wheel-20), [AS-WHEEL-21](scenarios.md#as-wheel-21), [AS-WHEEL-22](scenarios.md#as-wheel-22).

**Сценарии:** [AS-UI-12](../../../../requirements/current/ui/scenarios.md#as-ui-12-утерянная-сессия-и-сохранение-черновика), [AS-UI-13](../../../../requirements/current/ui/scenarios.md#as-ui-13-rate-и-capacity-до-запуска-build), [AS-UI-14](../../../../requirements/current/ui/scenarios.md#as-ui-14-неопределённый-исход-commit-и-timeout), [AS-UI-16](../../../../requirements/current/ui/scenarios.md#as-ui-16-две-вкладки-и-superseded), [AS-UI-18](../../../../requirements/current/ui/scenarios.md#as-ui-18-пустой-поиск-и-отказ-каталога), [AS-UI-23](../../../../requirements/current/ui/scenarios.md#as-ui-23-потерян-ответ-build).

При отказе клиент сохраняет черновик даты, времени/отметки и подтверждённого выбора места в текущей вкладке. Ответ определяет следующий запрос и показанное состояние:

| Полученный ответ | Следующий запрос клиента | Состояние экрана и действие пользователя |
|---|---|---|
| `409 SESSION_REQUIRED/EXPIRED/NOT_FOUND` | `POST /session/bootstrap {}` → `GET /charts/current`. | Показать действительное состояние новой/восстановленной сессии и сохранить черновик; новый build только по явному действию. |
| `409 RESULT_SUPERSEDED` или `200 already_applied` | `GET /charts/current`. | Показать фактическую карту из GET; не выдавать ответ POST за новую карту. |
| `429` или pre-admission `503 BUILD_CAPACITY_EXHAUSTED` | Автоматического повторного POST нет. | Показать `Retry-After`; после него предложить пользователю явное повторное действие. |
| `503 STATE_READ_FAILED` | Повторить безопасное чтение после восстановления доступности; cookie сохраняется. | Сохранить форму и сообщить о временной невозможности чтения. |
| `503 STATE_COMMIT_FAILED` | После `Retry-After` выполнить только `GET /charts/current`. | Исход build пока неопределён; показать результат сверки, не повторять POST автоматически. |
| `504 BUILD_TIMEOUT` | После `Retry-After` и подтверждённого restart/readiness выполнить bootstrap → current. | До сверки не объявлять build ни успешным, ни неуспешным и не отправлять POST автоматически. |
| Ответ POST потерян из-за обрыва соединения, сетевой ошибки или закрытия вкладки; HTTP status и `ErrorDTO` неизвестны | После возвращения связи выполнить только bootstrap → current. Отсутствующий `Retry-After` не выдумывать. | Сохранить доступный черновик. До сверки сообщить: «Не удалось получить ответ о построении карты. Проверяем текущую карту». Если current содержит карту исходного намерения, показать её; если карта другая, показать актуальную карту и сохранить черновик. Если current показывает старую/пустую карту, показать «Что-то пошло не так. Новый результат пока не появился. Введённые данные сохранены. Вы можете построить карту ещё раз; предыдущий расчёт может завершиться позже» и активное «Построить ещё раз». Если bootstrap/current не удался, оставить исход неопределённым и предложить повторить только безопасную проверку карты. |

Если после подтверждённого restart GET возвращает `empty` или старую карту, новый POST возможен только по явному действию. При потере ответа владелец выбрал вариант B: после **успешного** bootstrap → current со старой/пустой картой новый POST разрешён только по отдельному нажатию «Построить ещё раз» при действующей ручной отметке ADR-0034, без повторного ввода даты, времени и места. Если вкладка открылась заново и отметка сброшена, пользователь ставит её вручную. Такой GET не доказывает завершение первого build; UI не утверждает, что расчёт не удался, и после повторного POST показывает только фактический committed результат либо снова сверяет current по полученному outcome. Пока bootstrap/current не ответил успешно, повтор build недоступен. Когда вкладка B явно построила карту, возврат вкладки A выполняет bootstrap → current и показывает сохранённую B карту; локальный `state_version` A не является серверным expected version. Решение владельца зарегистрировано в DP-UI-09 @ `64934fc`; контракт повторно сверён Tester @ `0f6aa82`, утверждение Manager для реализации — в связанном Change Plan.

**Добавка M1-8:** Последняя подтверждённая карта с колесом/сводкой может оставаться при отказе чтения/build с ясным состоянием проверки; подтверждённый empty/unavailable удаляет числовое представление. Recovery intent, локальный черновик и фактически показанная карта различимы. Нужные сообщения, Retry-After/restart gate и безопасный recheck не исчезают в скрытой форме. Повторное отображение, выбор и изменение ширины не выполняют POST. Политика выбора после безопасного чтения той же identity остаётся DP-O-013; её нельзя выводить из принятого сохранения при resize. Локальный отказ SVG сохраняет HTML и подтверждённые данные по DP-O-010, не подменяя действующий recovery отказа HTTP.

### REQ-UI-11. Сводка показанной карты и раскрытие формы

**Операция:** ADD. **Исходный пункт:** отсутствует; связаны REQ-UI-01/03/08/09 @ MainBaseline. **Целевой пункт:** `docs/requirements/current/ui/birth-form-and-facts.md#req-ui-11`.
**Основания:** DP-O-002/003/013. **Сценарии:** [AS-WHEEL-01](scenarios.md#as-wheel-01), [02](scenarios.md#as-wheel-02), [12](scenarios.md#as-wheel-12), [18](scenarios.md#as-wheel-18), [21](scenarios.md#as-wheel-21).

После successful committed build либо восстановленного chart_ready показываются дата, место и известное HH:MM / явная неизвестность времени именно показанной карты, колесо и «Изменить данные». Для committed POST источник сводки — неизменяемый снимок отправленных birth_date/birth_time/place_id и подтверждённое название выбранного места, связанный с identity ответа. POST не содержит BirthViewDTO: tz_id/offset и иные resolved поля не выдумываются и дополнительный GET ради сводки не требуется. Для current source — birth из того же ответа. Current chart_unavailable показывает сохранённую сводку с отказом изображения; empty не выдаёт прежний birth за текущую карту.

При первичном получении карты без изменённого черновика форма сворачивается, «Изменить данные» раскрывает заполненные текущие значения и имеет доступную подпись состояния. Это действие не отправляет запрос, не меняет карту/сводку и не отмечает checkbox за пользователя. При сохранённом изменённом черновике раскрываются именно его значения; серверный birth не затирает их. Пока явно не принят новый результат, сводка остаётся связана с прежней картой, а редактор ясно обозначен как несохранённый ввод. После reload ручная отметка условий снята. Повторный отказ build сохраняет черновик и прежнюю сводку; подробности состояния формы/фокуса при новом результате, recovery и отмене редактирования требуют DP-O-013. Автоматическое скрытие несохранённого черновика этим пакетом не принято.
