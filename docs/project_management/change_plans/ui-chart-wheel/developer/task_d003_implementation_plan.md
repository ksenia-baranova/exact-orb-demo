### G. CSS-координаты, bounds, gap и допустимые движения — R01 / C02

**G1. Единая система.** Все входы measurement record — CSS px относительно левого верхнего угла viewport: x вправо, y вниз. Это не device pixels и не координаты PNG. Фиксируются viewport / scroll offset / DPR / zoom=100%, SVG viewBox, CSS content box и полная affine matrix `M=(a,b,c,d,e,f)` от локальных SVG units до этого viewport. Матрица применяется и к координатам, и к векторам размеров; прямоугольники получаются после transform в CSS. Screenshot той же записи содержит DPR / crop mapping; screenshot pixels не сравниваются с CSS порогом без этого mapping. Изменившийся layout / scroll / font / scale означает другой measurement record, а не смешивание чисел двух состояний.

**G2. Reference и ошибка anchor.** Для каждого point ID неизменный true reference `A_i` задаётся независимой таблицей из опубликованной longitude, принятой ориентации, фиксированного центра C и номинального label-ring radius r_i. Натал использует фактический опубликованный ASC, cosmogram — 0° Овна; относительно него 0/90/180/270 находятся left/bottom/right/top. В локальной равномерной системе это `A_i=(Cx-r_i*cos(alpha), Cy+r_i*sin(alpha))`, затем M переводит его в CSS; alpha — разность опубликованных долгот, без вычисления знака / дома / аспекта. Expected reference формируется отдельно от placement-кода; cardinals имеют отдельную таблицу ожидаемых сторон. Фактическая истинная отметка `A_actual` и её expected reference сравниваются по евклидовой норме `sqrt(dx²+dy²) ≤ 0,5 CSS px`, равенство проходит. Это допуск точности привязки, не разрешённый размер смещения label.

Display reference `P_i` — явно отмеченный origin жёсткой label-группы, совпадающий с A_i при default. Reference не извлекается из изменяющегося левого края / центра bbox. Меньшие внутренние радиусы для true ticks / концов аспектов имеют свои `E_i` той же longitude; стандартный радиальный отступ A_i от E_i не считается displacement. Концы аспектов, cusp / angle anchors и соответствие ID→longitude не двигаются. Для ☌ reference задан парой DTO и отдельным фиксированным marker-ring: берётся направление середины меньшей ориентированной дуги двух опубликованных концов; при совпадении — направление конца, при равных полуокружностях — направление from + положительная половина дуги. Это геометрическая reference-конвенция DRAFT, не поиск / пересчёт conjunction. Одна пара сохраняет свой key / оба конца; background не получает ☌. Сдвиг маркера не удлиняет хорду и не изменяет опубликованную пару.

**G3. Что двигается и что входит в bounds.** Перемещаемая единица point — glyph вместе с его R; единица ☌ — символ и отдельная подпись категории. Их внутренние offsets фиксируются до сравнения, шрифт / контур / stroke / hit size не уменьшаются при проверке варианта. Выбранный ☌ имеет контур только символа, не общую рамку с подписью. Для каждого состояния normal / selected / focused сохраняются отдельные component bounds: ink glyph, ink R, category text, painted stroke / contour и focus indicator. Measurement contract использует **конечное объединение закрытых axis-aligned CSS rectangles этих компонентов по всем проверяемым состояниям** `V_i=union(B_i,k,state)`. Пустота между компонентами не заполняется enclosing bbox всей группы. Rotation / skew требуют CSS enclosing rectangle каждого компонента отдельно; возможная консервативность такого компонента записывается. Нельзя одновременно считать один component tight outline в одном запуске и AABB в другом.

Фиксированы кольца / zodiac / cusp lines, истинные отметки и концы аспектов, numeric HTML, C / M / ring parameters, angle labels / их bounds как препятствия, неконфликтующие label-группы. Decoration chords могут пересекаться и не являются label-collision obstacles; bounds надписей / символов / R / focus — являются. Effective hit shapes учитываются отдельно: одно только перекрытие двух областей 44×44 **не** разрешает смещать визуально неконфликтующие points.

**G4. Gap.** Для двух component rectangles A и B положим `dx=max(A.left-B.right, B.left-A.right, 0)`, аналогично dy. Квадрат евклидова расстояния — `dx²+dy²`. Для групп берётся минимум по всем парам component rectangles в их union; не расстояние между group enclosing boxes и не axis-padding. Условие — **gap≥2**, то есть minimum squared distance ≥4; ровно 2 проходит, overlap / касание дают gap=0 и не проходят. В аналитических controls decimal входы переводятся в точные рациональные числа; не используется дополнительный epsilon или округление до целого CSS px. В реальном будущем record сохраняются исходные числа / их происхождение / погрешность; если uncertainty не позволяет различить границу, вывод INDETERMINATE, не PASS. Допуск 0,5 для anchor к gap / clipping не применяется.

**G5. Исходные конфликты / frozen set.** Из default bounds всех состояний до размещения фиксируется C0: label-группы с gap<2 к другой группе / фиксированному визуальному obstacle. Только группы C0 могут менять P_i; все остальные P_i и component bounds заморожены. Общий group enclosing box / hit overlap не расширяют C0. Нарушенный default clipping / запрещённый регион у группы вне C0 — контрпример исходного frame, а не разрешение молча сдвинуть её. Новая коллизия с frozen объектом запрещает кандидат; frozen объект не передвигается и не добавляется в C0 задним числом. Sparse имеет пустой C0, displacement=0, leaders=0.

**G6. Ring bounds и область.** До первого измерения фиксируется frame record с конечными числовыми `C`, `r_reference`, `r_inner`, `r_outer` отдельно для point-label ring и marker ring, а также списком clip regions и неподвижных препятствий. Это вход fixture / geometry contract с hash, не числа, подогнанные по результату. Равномерный SVG→CSS scale / translation разрешён; неравномерный scale / skew для кольца требует отдельного явно заданного CSS-path contract и независимого oracle, иначе frame NOT_READY. Каждый r неотрицателен, `r_inner ≤ r_reference ≤ r_outer`.

Для этой v2 label reference движется **по своей окружности фиксированного r_reference**, направление / путь к default описаны L1. Группа сохраняет ориентацию текста в CSS и перемещается жёсткой трансляцией; радиальное перемещение, смена кольца, вращение шрифта и перемещение соседей не входят в эту пробу. Каждый point каждого component rectangle V_i обязан лежать в закрытом annulus `r_inner ≤ norm(p-C) ≤ r_outer`, в effective clip C_clip и допустимой области viewport; равенство на границе допускается. Для AABB максимум радиуса находится среди углов, минимум — расстояние C до rectangle. Поэтому одной проверки display reference на допустимом радиусе недостаточно. Для glyph / R / ☌ / категории / selected contour / focus indicator проверяется весь union, а не только центр.

Допустимая область группы — пересечение объявленной окружности reference, полного containment V_i в её annulus / clip, gap≥2 ко всем фиксированным остальным V_j и сохранённого cyclic order. Нет универсальных размеров колец, выведенных из viewport или текущего glyph: конкретные r — обязательные входы будущей controlled fixture, фиксируются до запуска в TASK-D-003. Missing / изменяемые после measurement ring bounds дают NOT_READY, не «без ограничений». Close angles остаются препятствиями; недостижимость внутри этой объявленной модели возвращается контрпримером, не принимается fallback. Возможность иного допустимого движения / радиуса может быть вариантом для Technical Reviewer / Analyst, но требует новой редакции contract до сравнения, а не незаметной смены ограничения.

Циклический порядок points задаётся `(longitude, ordinal canonical point ID из HTTP §7.2)` с фиксированным seam 0°; совпавшие longitude используют тот же ordinal. Для проверки через seam — непрерывная развёртка от заранее заданного первого ID, не повторная сортировка полученного placement. Tie-policy для совпавших markers — `(from ID ordinal, to ID ordinal, published type order)` с сохранением разных пар; направления пары не переиначиваются. Это presentation order, не proof уникальности key. Ни true anchor, ни ordinal не меняются при пробе. Leader появляется iff P_i отличается от default A_i; ненулевое субпиксельное смещение не превращается в ноль по допуску 0,5.

**G7. Clipping.** C_clip — пересечение видимой области viewport, SVG viewport / viewBox mapping, всех ancestor overflow clips, SVG clipPath / mask support и соседних скрывающих областей, если они влияют на видимость. Для visual bounds требуется полный containment **до** clipping; обрезанный остаток не подставляется как новый «меньший glyph». ViewBox сам не заменяет реальные overflow / clip правила: effect и geometry каждого ограничения записываются. Unsupported clip/mask geometry или неизвестный painted bound → UNPROVEN. Page overflow — отдельный predicate, его PASS не доказывает отсутствие SVG-clipping. Hit clipping и occlusion дополнительно проверяются H1; CSS background контейнера не считается видимым glyph.

### L. Допустимая проба возврата и предел доказательства — R02 / C01

**L1. Проба.** Для reference на окружности метрика displacement — длина меньшей дуги от A_i до P_i в CSS px: `d_i=r_reference*abs(delta_angle)` после fixed seam / tie policy. Anchor error из G2 при этом остаётся евклидовым. Return path q_i(s) идёт от P_i по этой же меньшей дуге к A_i на s CSS px, текст не поворачивается; на ровно полуокружности фиксируется положительное направление, одинаковое для default/probe. При `d_i>0` обязательная проба имеет длину **s=min(1,d_i)**. При d_i<1 это полный возврат к default, без overshoot; d_i=0 — несмещённая группа, probe N/A и leader отсутствует. При r=0 допустим только d=0, смещённый reference INVALID_FRAME. Прямой CSS chord к anchor не заменяет дуговой шаг. В горизонтальном аналитическом calibration primitive та же метрика — расстояние по заранее заданной прямой; этот primitive не добавляет второй способ перемещения actual SVG-кандидата.

**L2. Что проверяется.** Все остальные P_j / V_j, их состояния, anchors, C0 / rings / clip, font / stroke / focus и order заморожены. Переносится только жёсткая V_i по q_i; заново проверяются все predicates G3…G7 и leaders / ID mapping. **Допустима вся траектория** q_i([0,s]), а не только свободная конечная точка после прыжка через obstacle. Изменять размер, скрывать компонент, пересортировывать IDs / перестраивать соседей или вызывать placement helper при этой проверке нельзя. Verifier получает отдельный immutable measurement contract / input anchors / measured component geometry и не импортирует алгоритм размещения.

**L3. Раздельные выводы.** FEASIBLE означает выполнение G/H/F predicates только в текущей позиции. Если полная return-проба допустима — `LOCAL_STEP_FAIL`, сдвиг избыточен. Если нарушена — `LOCAL_STEP_PASS`, с указанием первого нарушаемого predicate / места; **это ещё не вердикт всей минимальности или компактности**. При непрерывных координатах нельзя объявить меньший допустимый возврат невозможным только потому, что полный шаг 1 нарушен.

Для завершённого локального обоснования compactness сохраняется независимый directional-boundary certificate: существует ли хотя бы одно `0<t≤min(1,d_i)` с допустимой всей prefix-траекторией q_i([0,t]). Если существует — кандидат избыточен (`LOCAL_TIGHT_FAIL`) и предъявляется конкретное t; если отсутствие такого положительного prefix доказано фиксированным активным ограничением — `LOCAL_TIGHT_PASS`; отсутствие certificate — `LOCAL_TIGHT_UNPROVEN`, не PASS. Это одномерная проверка возврата **одного** label при замороженных остальных, без поиска раскладки / другого кольца / коллективного перемещения и без требования глобального или субпиксельного оптимума всей карты. В общей геометрии boundary certificate может быть отдельным аналитическим обоснованием; эти controls не выдают ещё не написанный curved-path verifier за готовый.

**L4. Точность и дроби.** Decimal CSS координаты допустимы, сетка целых px не вводится. Сохраняются полные входные значения и матрица; для аналитических прямолинейных controls сравнение рациональное и точное. В будущем измерении для реальных кривых сохраняются formula/path и численная погрешность независимого вычисления; недоказанный знак / boundary interval → UNPROVEN, не скрытый epsilon. Само значение s=1 — согласованная проба, не допуск на избыточность и не разрешение округлить displacement<1 до нуля. Boundary certificate проверяет направление / ограничения; он не назначает новый размер шага или tolerance. Аналитический пример 0,5 ниже — различающий witness, не новый обязательный порог.

<a id="d004-font"></a>
### F. Что измеряют 16 / 12 CSS px — R03 / C02

**F1. Величина.** 16 для point / ☌ glyph и 12 для R / category text относятся к **эффективному em-size текста в CSS px после всех преобразований**, а не к фактической высоте ink bbox. При локальном font-size f и линейной части общей M величина равна `norm(M*(0,f))`; translation не влияет. Для HTML, уже выраженного в CSS viewport units без дополнительного transform, это computed font-size с учётом фактического CSS scale. SVG user units нельзя назвать CSS px до применения M. Для mixed-font / mixed-size runs каждый run проверяется отдельно. Это однозначная рабочая интерпретация прежнего «glyph не менее 16», вынесенная в DRAFT для смыслового подтверждения TASK-A-004; отдельный минимум ink-height не вводится.

**F2. Раздельные записи.** Сохраняются CSS computed font-size / units, effective em-size, actual resolved font каждого glyph / fallback, ink boxes, painted stroke / selected contour, focus indicator, M / zoom / DPR. Ink может быть ниже em (например em=16, ink height=12) и всё равно проходит **size predicate**; это не автоматическое подтверждение читаемости. Missing-glyph / tofu / пропущенная R или подпись дают READABILITY_FAIL даже при em≥порога. Настоящий fallback с нужным glyph допустим только как явно записанный resolved font с реальными bounds; неизвестный font / fallback даёт UNPROVEN. Нельзя увеличить stroke / focus box, чтобы «добрать» 16/12, либо уменьшать f / scale для плотного случая и продолжать считать nominal size выполненным. Contour / focus участвуют в G3/G4/G7, а не в размере em. Текстовые признаки типа / категории, неизменённая подпись ☌ и усиленный контур только символа наследуются из v3. Условия проверки увеличенного текста исходных требований не отменяются zoom=100% этой исследовательской клетки.

| F-size-boundary | Point/☌ effective em=16; R/category effective em=12, glyph присутствует | SIZE_PASS на равенстве; visual bounds / читаемость проверяются отдельно |
| F-size-below | Effective em=15,99 / 11,99 | SIZE_FAIL соответствующего run; округление не применяется |

### H. Effective hit area и живой focus — N01 / C03

**H1. Effective area.** Для canonical target i фиксируется native hit shape T_i с реальными SVG fill / stroke / pointer-events / CSS transform / visibility / enabled state, а не его enclosing bbox. Effective H_i — точки T_i внутри всех actual clips / viewport, в которых native topmost hit и последующая native pointer event принадлежат **живому** target i / его объявленному потомку и разрешаются в тот же canonical ID/пару. Из H_i исключаются перехватывающие overlay / соседние targets по paint order и области, где фактический handler не активирует нужный объект. Для nested child указываются native event.target, owner в composed path, instance / canonical key и фактическое selection outcome; nearest-ID / программная переадресация чужого target не является подтверждением попадания.

**H2. Порог 44×44.** Для каждого target предъявляется конкретный axis-aligned CSS **полуоткрытый** rectangle `Q_i=[x,x+w)×[y,y+h)` с w≥44, h≥44, целиком внутри H_i. Это доступная область попадания, не только размеры охватывающего bbox. Конкретный Q — вход проверки, verifier не ищет лучшее placement. Для rectangular native shape left/top принадлежат ему, right/bottom не входят в Q; пробы ровно справа / снизу проверяют объявленный соседний hit исход и не засчитываются как внутренняя площадь. Clip equality для ширины 44 допустимо, если весь такой half-open Q доступен. Для nonrectangular / сложного clip / overlay нужны исходная hit geometry и обоснование containment; неизвестная область → HIT_UNPROVEN, даже если несколько кликов успешны. Один bbox или центральный click не доказывает containment.

**H3. Native coordinate protocol, после отдельного допуска D003.** Для объявленного Q сохраняются actual requested / delivered CSS coordinates, topmost hit / composed path / canonical ID, state до / после. Выполняются настоящие pointer actions по координатам: center, сетка долей 0 / 1/4 / 1/2 / 3/4 по обеим осям, ближайшие представимые внутренние точки к right/bottom, отдельные boundary / outside probes, а также interior witnesses каждой clip/overlay boundary, пересекающей Q. Это позиции sampling, не новые размеры target. Проверяются все point / видимые ☌ targets, выбор другого и снятие; background — HTML с положительным exact/working control. Программные element.click()/dispatchEvent и один elementFromPoint без actual activation не являются native evidence. Конечный набор проб — чувствительный control, не математический proof всей H_i: нужен также containment из H2. При несовпадении geometry certificate и native event вывод FAIL / UNPROVEN, а не PASS по одному из источников.

Порядок групп фиксируется DOM / accessibility trace: существующие разрешённые editor / recovery controls, wheel point targets, видимые wheel aspect targets, HTML points, aspects и их reveal, houses / их reveal. | Таблица сузилась до 5 / одной строки из-за выбора планеты | Точка взаимодействия — сохранённый point-control, получивший focus обычным user input **до** фильтрации; никаких программных переводов на строку / reveal. Если browser/input оставил focus на исчезающей старой строке, такой renderer/control не проходит критерий: предложить совместимую native-focus конструкцию / counterexample Technical Reviewer, не автоматически применить fallback предыдущей строки |
| Явное раскрытие таблицы / разрешённое изменение editor state | Сохраняется живой инициирующий control, пока он остаётся доступен. При его исчезновении — fallback только для этого cause, не для planet-selection. Новая кнопка «Свернуть» не добавляется: сужение таблиц возникает только из уже принятого selection/reset поведения |
| Initial/own-success collapse без позднего draft | До скрытия полей определить, находится ли focus внутри них. Внутренний focus переносится на существующий «Изменить данные» без scroll с cause=accepted-build/collapse; focus снаружи сохраняется. Поздний отличающийся draft остаётся открытым; automatic current его не скрывает. Разрешённые recovery controls вынесены вне скрываемых полей и остаются reachable с действующими gates |

H5 не требует перемещения focus при каждом render. Удалённый / пересозданный control обязательно дополняется парным проходом с сохранённым node и последующей настоящей активацией; fallback cause / same-key restoration не применяются к выбору планеты.
