## Что делает код
`tests/acceptance/terms_acceptance.mjs:141-154` (сценарий `current`, карточка T-29) монтирует форму через `mount()` с уже сохранённой картой (`:10-18`, `:143`), редактирует дату, время и checkbox (`:145`), затем удерживает **второй** GET /charts/current через `session.foreground()` (`:147`), открывает условия и возвращается (`:149`), отпускает ответ и сравнивает черновик с исходным (`:151`).

Заполнение формы из current в production выполняется только один раз: `src/exact_orb/http_api/ui/main.mjs:134` требует `!birthRestored`, а `mount()` уже потратил это заполнение на первичном current (`main.mjs:146`). Кроме того, правки в `:145` сами ставят `draftProtected` (`main.mjs:220`). Поэтому утверждение `:151` не зависит ни от защиты черновика при открытии условий (`main.mjs:83`), ни от проверки `!draftProtected` (`main.mjs:134`).

## Сценарий поломки
Мутации production при неизменных тестах (рабочая копия, равная blob'ам HEAD `9bdb3e5`):

| Мутация `main.mjs` | Последствие для пользователя | `tests/ui/terms.test.mjs` | 7 сценариев `terms_acceptance.mjs` |
| --- | --- | --- | --- |
| Удалить `draftProtected = true;` в `openTerms` (`:83`) | Поздний первичный current во время чтения условий заполняет нетронутую форму, хотя черновик открыт для перехода | 4 FAIL | все PASS |
| Убрать `!draftProtected &&` из условия `:134` | Поздний первичный current затирает уже изменённый пользователем черновик (дата, место, время) | 8 FAIL | все PASS |

Итог: приёмочный PASS T-29 не может упасть на дефекте, который карточка проверяет («открытый D не перезаписан birth B»). Позитивного контроля из T-29 («Контроль без изменённого D — действующее восстановление current») в сценарии тоже нет. Сейчас поведение защищено только тестами Developer `tests/ui/terms.test.mjs:150-173`.

## Как исправить
Изменить только приёмочный тест, production не трогать:
1. В сценарии `current` удерживать **первичный** GET /charts/current, то есть не ждать `ui.ready` до правок. Пример — `mountPendingCurrent` в `tests/ui/terms.test.mjs:142-148` или `deferred` из `tests/ui/fixtures/session.mjs`.
2. Изменить D, открыть условия и отпустить ответ в двух отдельных проходах: во время чтения и после каждого возврата. Затем проверить равенство черновика.
3. Добавить позитивный контроль: тот же поздний первичный current без правок и без открытия условий заполняет форму сохранённым birth.
4. Ожидаемый результат для нетронутой формы, открытой для чтения, — после решения [DP-R-01](../dp/DP-R-01.md).

## Если не исправить
Регрессия защиты черновика в `main.mjs:83/134/220` пройдёт приёмку. Независимое evidence REQ-TERMS-04 для поздних ответов фактически отсутствует, хотя матрица и T-29 показывают PASS. Пользователь с медленным первичным чтением может потерять введённые дату, место и время, и приёмка этого не заметит.
