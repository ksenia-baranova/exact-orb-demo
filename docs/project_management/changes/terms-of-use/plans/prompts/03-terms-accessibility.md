## Структура
Ссылка и пояснение неизвестности получают одинаковые computed family/size/weight, исходно 13 px. Размер области обеспечивается layout/padding, отдельно от текста; ссылка вне label, нативные кнопки type=button вне form. Сохранить общий focus-visible, перенос длинных строк и узкое представление таблицы контуров.
Фокус открытия — heading условий; возврата — ссылка в видимой раскрытой форме. Hidden-страница не оставляет доступных для Tab контролов. Логирование и новые сетевые сервисы не добавляются; счётчик POST измеряется после завершения исходного открытия.

## Шаги
1. Подход тест → код для найденного дефекта; если поведение уже выполнено 01/02 — существующие terms/delivery тесты плюс новая браузерная проверка наблюдаемого результата. Исправлять только страницу и её связь с формой; дефект закрепить детерминированной проверкой.
2. В настоящем браузере открыть реальные package assets на desktop и 360 px: Tab/Enter открывают ссылку, видно heading focus; обе кнопки доступны клавиатурой, возвращают focus в форму. Проверить computed font по всем трём свойствам, читаемость полного текста и отсутствие горизонтального overflow в начале и конце страницы.
3. Для ссылки и двух возвратов проверить эффективные 44 × 44 CSS px доверенным pointer и фактическим elementFromPoint/получателем click. Позитивный контроль: вся проверяемая область активирует нужное действие. Негативные: меньшая область, перекрытие и clipping в контролируемом fixture должны быть обнаружены той же проверкой; bbox/CSS min-size сами по себе не evidence.
4. Различить действия: ссылка открывает текст без переключения отметки; checkbox переключает отметку без перехода. Оба возврата сохраняют ввод и не добавляют POST; отдельное валидное построение служит позитивным контролем сети. Проверить reload и закрытие/повторное открытие после ручной отметки и после «Согласен», с восстановленной картой и без неё: отметка снята.
5. Сверить C1…C8 и видимые абзацы/ссылки с утверждённой редакцией, точный контакт exact_orb@mail.ru, отсутствие редакционных меток. Проверить бесплатно доступный полный исходный код точной используемой версии и записать source commit/URL, способ сверки, delivery commit и результат. Если код этой версии ещё не опубликован — назвать C7 непроверенным, не выполнять push по этому промту.
6. Записать evidence: точные команды/браузер/viewport, commit, snapshots и результаты контролей. Упрости затронутые CSS/handlers, сохрани тесты публичного поведения; не добавляй общий UI framework или новую зависимость.
