### REQ-WHEEL-04. Состав аспектов и соединения

**Основания:** DP-O-006, DP-O-007, DP-O-008, DP-O-013 (S1 @ AssignmentSHA); единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-06](scenarios.md#as-wheel-06), [AS-WHEEL-07](scenarios.md#as-wheel-07), [AS-WHEEL-08](scenarios.md#as-wheel-08), [AS-WHEEL-11](scenarios.md#as-wheel-11), [AS-WHEEL-28](scenarios.md#as-wheel-28), [AS-WHEEL-30](scenarios.md#as-wheel-30).

Без выбора аспекта графически представлены все и только опубликованные exact/working аспекты независимо от type, кроме явно принятого исключения S1 для неоднозначной пары/type ниже. В режиме выбранного аспекта графический набор ограничен одной выбранной парой по REQ-WHEEL-07; исходный DTO сохраняется, отображаемый subset определяется REQ-WHEEL-07. Для остальных типов линия соединяет истинные долготы обоих endpoint IDs, разрешённых HTTP §7.2: points либо asc/mc/vertex. Аспект с углом не отбрасывается и не превращается в связь с ближайшей планетой; dsc/ic не добавляются в аспектную сетку. Для отображаемого conjunction есть различимый маркер ☌, связанный с конкретной опубликованной парой, и точная запись пары в HTML. Искусственное удлинение геометрии и повторный поиск аспектов не допускаются. Background остаётся только в полном табличном списке; при выборе показываются его два конца без линии и без маркера ☌. Если exact/working отсутствуют, колесо с точками остаётся видимым, а отсутствие графических аспектов явно отличимо от отсутствия карты. Переключателей категорий и новых фильтров типов нет.

**Исключение S1 / DP-O-013 @ AssignmentSHA:** адрес аспекта — неупорядоченная пара канонических endpoint IDs вместе с опубликованным `type`. Для адреса учитываются все исходные записи `aspects[]` принятого DTO до five/all и planet-filter; одинаковые записи тоже считаются отдельными. Один match однозначен: единственная обратная запись `to→from` остаётся обычным аспектом, её from/to не переставляются в таблице. Более одного match — ambiguous, включая одинаковый duplicate, reversed duplicate и разные category / orb одной пары/type. Category и orb не разделяют такой адрес; другая опубликованная type образует другой адрес. Это правило адресуемости представления, не новая API identity или validation.

У ambiguous группы не показываются линия / маркер ☌ и недоступен выбор аспекта из HTML через pointer или keyboard. Все её исходные HTML-строки, DTO order, from/to, type, category, orb и числовые факты сохраняются без объединения / дедупликации / пересчёта. Five/all и planet-filter применяются к исходному набору по REQ-UI-06; warning — REQ-WHEEL-10. Остальные адреса, точки, дома и углы той же карты не объявляются ошибочными. Их графика / выбор действуют по прежним правилам, включая режим одной выбранной однозначной пары. Ambiguous не означает absent / пустой список / whole-wheel failure и не включает S2 с выбором отдельного occurrence.

Для cosmogram используются круговые ряды без присвоения вымышленных домов.

Каждая опубликованная точка сохраняет canonical ID, точные данные и истинную отметку source longitude. Концы аспектов привязаны к точным долготам, а не к перемещённому значку. Внешняя планетная колонка и planet leaders удалены; локальные маршруты вспомогательных обозначений не являются такой колонкой.

Скрытие ID/R, уменьшение символов ради прохождения измерения и синтез фактов не допускаются. Реализованные размеры glyph16/R12 — параметры текущего технического варианта, а не новые универсальные числа Owner. Остаточный независимый oracle плотности, допуск измерения gap2 и radial accuracy отложены в [DEBT-UI-004](../../../project_management/technical_debt.md#debt-ui-004); старые C0/frozen/global-minimality сертификаты другой construction не доказывают новый layout.


<a id="req-wheel-06"></a>
### REQ-WHEEL-06. Различение категорий и типов

**Основания:** DP-O-012; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-08](scenarios.md#as-wheel-08).


Линии опубликованных exact / working аспектов различаются рисунком: exact — сплошная, working — пунктирная. Тип различается цветом и текстом в легенде / HTML; штрих не обозначает тип. Выбранный линейный аспект сохраняет цвет / рисунок и получает усиленное выделение. Пара, type, category и опубликованный orb доступны текстом.

Легенда семи типов соответствует используемой графике и общей палитре HTML/SVG. На SVG нет слов «точный» / «рабочий» рядом с ☌: это более позднее прямое решение Owner19.10; тип / категория остаются в HTML. Выбранный ☌ имеет усиленный контур самого символа. Background не получает линии / ☌ даже при выборе. Пороги категорий и orb не меняются; измерительные ограничения плотности остаются DEBT-UI-004.


<a id="req-wheel-07"></a>
### REQ-WHEEL-07. Выбор через HTML и отдельный просмотр аспекта

**Основания:** DP-O-008, DP-O-010, DP-O-013; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-27](scenarios.md#as-wheel-27), [AS-WHEEL-11](scenarios.md#as-wheel-11), [AS-WHEEL-12](scenarios.md#as-wheel-12), [AS-WHEEL-13](scenarios.md#as-wheel-13). [AS-WHEEL-28](scenarios.md#as-wheel-28).


SVG — пассивное изображение, без pointer/keyboard controls и без самостоятельного выбора points, аспектов, углов или домов. Пользователь выбирает каноническую планету/точку либо однозначный опубликованный аспект только через HTML. Состояния взаимоисключающие: один point, один аспект или ничего; подсветка двух концов аспекта не означает выбор двух планет.

Другая планета заменяет прежнюю. Таблица аспектов показывает все исходные from/to выбранного ID с остальной картой, включая background и опубликованные angle endpoints, без лимита пяти и в DTO order. Никакие пары не рассчитываются. Пустой отбор отличается от пустой карты. Выбор планеты обновляет представление на месте, без автоматической прокрутки и переноса focus; раскрытие таблицы points сохраняется.

Выбор однозначного аспекта снимает планетный отбор и открывает отдельный режим чтения: одна строка аспекта, его опубликованные participants (до двух points, в том числе за пределами первой пятёрки), их дома при наличии. Непричастные части общей композиции могут быть скрыты; исходный полный DTO не меняется. У angle endpoints и неизвестного времени вымышленные дома не появляются. Для exact/working показаны только выбранная линия / ☌ и два конца; для background — только два конца без линии / ☌.

Режим имеет доступный возврат, включая Escape. При входе focus/scroll направлены к области чтения и доступному возврату; при выходе восстанавливаются прежние независимые раскрытия и живой исходный HTML-control. Это позднее разрешённое поведение выбора аспекта, оно не меняет запрет focus/scroll при выборе планеты. Повтор той же строки также может снять выбор. Выход не восстанавливает старый planet-filter. Интерпретации / LLM-вызова или HTTP это не добавляет.

S1: неоднозначные группы по REQ-WHEEL-04 остаются читаемыми, но их aspect-select недоступен. Все исходные строки / значения сохраняются; point selection / другие уникальные адреса работают. Неоднозначность не снимает присутствующий point selection и не превращается в whole-wheel failure.


<a id="req-wheel-08"></a>
### REQ-WHEEL-08. Снятие и принадлежность выбора карте

**Основания:** DP-O-008, DP-O-013; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-13](scenarios.md#as-wheel-13), [AS-WHEEL-14](scenarios.md#as-wheel-14), [AS-WHEEL-15](scenarios.md#as-wheel-15), [AS-WHEEL-17](scenarios.md#as-wheel-17), [AS-WHEEL-18](scenarios.md#as-wheel-18). [AS-WHEEL-29](scenarios.md#as-wheel-29), [AS-WHEEL-30](scenarios.md#as-wheel-30).

Повторная активация выбранной планеты снимает её выбор / подсветку и отбор aspects: сразу видны первые пять общего списка с отдельной кнопкой «Показать все». Это прежнее принятое правило не заменяется правилом снятия аспекта. Отдельная кнопка «Снять выделение» не добавляется.

Повторная активация выбранного аспекта через его HTML-строку или доступный возврат режима чтения снимает выбор. То же действие доступно с клавиатуры. Возвращаются обычный графический набор exact/working и общий список aspects с прежним состоянием его раскрытия: первые пять либо все. Прежний планетный фильтр не восстанавливается. Сохранённое раскрытие относится к обычному списку, а не к единственной строке выбранного аспекта; houses от этого действия не меняются.

При полной перезагрузке F5/«Обновить» выбор / подсветка и раскрытие таблиц сбрасываются; восстановленный current рисует карту заново с первыми пятью points / aspects / houses. Отдельно сохраняется reset при принятии новой карты после успешного явного build по изменённым birth data. Изменение полей, отказ build и неопределённый исход сами по себе не заменяют принятую карту и не являются этим событием reset. При resize выбор и раскрытие сохраняются, HTTP нет.

Автоматическое чтение при возвращении видимой вкладки / online само по себе не сбрасывает выбор и раскрытие. Отдельное событие принятия нового результата собственного явного build по изменённым birth data сохраняет правило reset выше; оно не определяется одним лишь HTTP-методом источника ответа. При chart_ready с той же или другой identity сохраняется только выбор, адресуемый опубликованным объектом / однозначным аспектом нового ответа; показываются его новые факты. Если выбранный объект / аспект отсутствует, снимается только этот исчезнувший выбор, раскрытие таблиц сохраняется. Это прямо подтверждённое Owner исключение; полный reset при любом отличии identity не вводится. Например, natal moon→asc не переносится на cosmogram без angles. При снятии исчезнувшего выбора действует общий список с сохранённым раскрытием, а не старые данные / вымышленная пара. Ошибка чтения не доказывает исчезновение выбранной записи. Подтверждённые empty / unavailable убирают колесо и выбор по действующему контракту; старые числовые факты не переносятся на состояние без ChartDTO.

**S1 при принятии DTO:** если в сохраняющем состояние пути ранее выбранный аспект получает больше одного match пары/type, снимается только его aspect selection, а не выбор / данные всей карты. Общий список возвращается с сохранённым раскрытием aspects; независимое раскрытие houses и открытый draft сохраняются, прежний планетный фильтр не восстанавливается. Новые строки / warning / графика относятся только к принятому DTO; старые category / orb / линия не удерживаются. Присутствующий выбранный point сохраняется и показывает все свои новые строки. Это отдельное исключение, а не доказательство исчезновения: 0 matches — absent, 1 — обычное сохранение с новыми фактами, >1 — S1. Ошибка / непринятый ответ не меняют cardinality подтверждённой карты и сами не снимают выбор. Когда последующий принятый DTO снова однозначен, графика и возможность выбора восстанавливаются по общим правилам; ранее снятый выбор автоматически не создаётся. S1 не отменяет отдельные F5, принятие результата явного build по изменённым birth data и подтверждённые empty / unavailable: их прежние reset / removal правила выше сохраняются. Из-за ambiguity HTTP / новый build / изменение draft не выполняются.

Поздняя политика Owner20.10: committed changed-birth, fresh matched recovery и already_applied с живой целью и fresh GET birth=B используют reset один раз. Collapse допустим только при current draft=B; same-birth не требует reset. Failed/stale/different/empty GET и RESULT_SUPERSEDED не доказывают подтверждение своей цели; последующий обычный current сохраняет выбор/раскрытия и пользовательски открытый editor. Подробнее — REQ-UI-09/11.

### REQ-WHEEL-09. Композиция и независимое раскрытие таблиц

**Основания:** DP-O-001, DP-O-002, DP-O-003, DP-O-011, DP-O-013; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-26](scenarios.md#as-wheel-26), [AS-WHEEL-01](scenarios.md#as-wheel-01), [AS-WHEEL-02](scenarios.md#as-wheel-02), [AS-WHEEL-16](scenarios.md#as-wheel-16).


Колесо появляется сразу после принятого committed/current ChartDTO, независимо от раскрытия таблиц. На desktop оно рядом с краткой сводкой, при сужении — под ней. Форма до карты центрирована; принятая карта использует фактическую конечную ширину контейнера до первого draw, без временного узкого кадра.

Все три обычные HTML-таблицы — «Планеты и точки», рассчитанные дома, аспекты — начинают с первых пяти строк в исходном порядке (дома по number). У каждой собственные «Показать все» / «Показать первые 5»; при пяти или меньшем числе строк лишняя кнопка скрыта. Раскрытия независимы, запрос не выполняется. Ограничение points относится только к HTML, полный SVG-набор не сокращается.

Выбор планеты показывает все её опубликованные аспекты без лимита пяти. Режим аспекта показывает всех его participants и соответствующие опубликованные дома, скрывает неприменимую кнопку раскрытия, при выходе возвращает прежние раскрытия. Опубликованные angles, включая Vertex, доступны отдельным компактным блоком; отсутствующие angles/houses cosmogram не синтезируются. Общий gate подробностей не скрывает первые строки таблиц.

На 360 px нет горизонтального overflow страницы, источник данных остаётся читаемым в HTML. Контрольные ширины — 1440/768/360. Resize сохраняет допустимый выбор и раскрытия, обновляет представление без HTTP / пересчёта фактов. Пределы плотности и численной geometry-проверки — DEBT-UI-004, не универсальный PASS.


<a id="req-wheel-10"></a>
### REQ-WHEEL-10. Доступное HTML-управление и локальный отказ SVG

**Основания:** DP-O-008, DP-O-010, DP-O-011, DP-O-012, DP-O-013; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-16](scenarios.md#as-wheel-16), [AS-WHEEL-23](scenarios.md#as-wheel-23), [AS-WHEEL-24](scenarios.md#as-wheel-24), [AS-WHEEL-28](scenarios.md#as-wheel-28), [AS-WHEEL-30](scenarios.md#as-wheel-30).


Пассивное SVG имеет текстовые название/описание, не содержит tab stops, selectable hit targets или SVG-активации. Полные canonical факты доступны в HTML без hover. Нативные HTML-controls выбора и раскрытия доступны pointer/keyboard, имеют видимый focus и effective Q44 внутри фактической hit area с учётом clips/overlap. Исправление TEST-FIND-WHEEL-004 проверено независимо; DEBT-UI-004 не отменяет это обязательство.

Повторная активация выбранной планеты снимает её выбор; общего нового «Снять выделение» для points нет. Выбор планеты сохраняет focus/scroll. Для отдельного чтения аспекта действует разрешённый переход и возврат REQ-WHEEL-07. Категория линии различима по рисунку, тип дополнен текстом, интерфейс не зависит только от цвета.

Если SVG не отрисован, HTML и подтверждённые данные той же принятой карты остаются доступны, показано локальное сообщение ошибки изображения. Изображение старой A не остаётся рядом с HTML новой B; отказ изображения не становится ошибкой расчёта, отсутствием ChartDTO или HTTP recovery, не запускает build и не уничтожает данные. Неожиданная ошибка controller/HTML сохраняет существующий safe-read/fallback, а не маскируется под штатный SVG failure.

Для ambiguous группы S1 доступный текст называет пару/type, объясняет несколько исходных записей и локальную недоступность графики/выбора. Все строки остаются читаемыми; другие пары / points продолжают работать, whole wheel не скрывается. Warning доступен без раскрытия всех строк, не сбрасывает раскрытия/draft и не вызывает HTTP. DOM/ARIA-реализация не вводит новый публичный API.

### REQ-WHEEL-11. Проверяемые переходы и наблюдаемость

**Основания:** DP-O-010; единый реестр @ InputSHA. **Сценарии:** [AS-WHEEL-01](scenarios.md#as-wheel-01), [AS-WHEEL-02](scenarios.md#as-wheel-02), [AS-WHEEL-17](scenarios.md#as-wheel-17), [AS-WHEEL-18](scenarios.md#as-wheel-18), [AS-WHEEL-19](scenarios.md#as-wheel-19), [AS-WHEEL-20](scenarios.md#as-wheel-20), [AS-WHEEL-21](scenarios.md#as-wheel-21), [AS-WHEEL-22](scenarios.md#as-wheel-22), [AS-WHEEL-24](scenarios.md#as-wheel-24).

Сетевой путь сохраняет текущие request_id, run_id для build, http_request_started, фактические http_message send/receive и terminal http_request_finished. UI-переход принятия результата → колесо / таблицы, источник POST / current, смена identity, взаимоисключающий выбор / повторное снятие планеты или аспекта, сохранение / снятие исчезнувшего выбора при automatic current, локальный отказ SVG и раскрытие таблиц подтверждаются упорядоченным браузерным или интеграционным evidence для той же карты. Отдельно наблюдаются нормальные HTML данные и сообщение отказа колеса; серверный HTTP success не доказывает успешный SVG render. Серверный журнал не обязан писать каждое нажатие — baseline AS-UI допускает browser evidence. Новый runtime logger, телеметрия и сеть этим пакетом не вводятся. Developer определяет проверяемый UI seam в DP-O-010; технические sequences и payload logs сохраняют действующие ADR / уровни.
