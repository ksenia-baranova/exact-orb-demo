## Глоссарий

| Термин | Значение |
| --- | --- |
| Форма | Экран ввода даты рождения, места из каталога и местного времени до минуты |
| Черновик формы | Текущая дата, текст поля места, выбранное место с place_id и отображаемым названием, строка времени и отметка «Точное время неизвестно»; значения могут быть пустыми или незавершёнными |
| Checkbox / отметка ознакомления | «Я ознакомился с условиями сервиса»; локальное состояние «снят» или «выбран» |
| Страница условий | Отдельная страница «Условия использования сервиса», открываемая текстовой ссылкой под checkbox |
| Возврат | Действие «Согласен» либо «Вернуться к форме» на странице условий к форме, из которой открыта страница |
| Новая загрузка формы | Первое открытие формы, reload либо повторное открытие после закрытия; возврат кнопками страницы условий новой загрузкой не считается |
| Текущий переход | Открытие условий из формы и один из двух возвратов без новой загрузки |
| Явное построение / POST | Отдельное действие пользователя, отправляющее POST /charts/natal по REQ-UI-03 и REQ-UI-09 |
| Валидные поля | Дата проходит локальную календарную проверку, место выбрано из каталога, время соответствует HH:MM либо явно неизвестно; серверная проверка остаётся отдельной |
| Принятая карта | Результат, полученный через действующий HTTP-контракт; чтение условий не создаёт новую карту |
| Сессия | Анонимное состояние на сервере, связанное с браузером session cookie; содержит исходные и разрешённые данные рождения, параметры и сохранённую карту |
| Расчётный кэш | Отдельный process-local LRU с сериализованным артефактом расчёта; TTL настраивается независимо от сессии |
| Журнал | Операционные и диагностические записи сервера с отдельной ротацией; полный payload границ доступен при DEBUG |
| HTTP API | Действующий транспорт build, bootstrap, current и поиска мест |
| Утверждённый текст | Редакция условий, для которой записано решение Owner; черновик Analyst этого статуса не имеет |
| Контакт владельца | Выбранный Owner адрес `exact_orb@mail.ru` для личных обращений по вопросам данных и удаления; публичный GitHub issue не назначен таким каналом |
| Исходный код | Бесплатно доступный полный исходный код используемой версии проекта |

<a id="req-terms-01"></a>
## REQ-TERMS-01 Открытие отдельной страницы

Система должна открывать отдельную страницу «Условия использования сервиса» по одноимённой текстовой ссылке под checkbox формы.

Шрифт ссылки совпадает с шрифтом пояснения «Карта будет без асцендента и домов.» под «Точное время неизвестно»: семейство, размер, начертание. На базе размер пояснения 13 px; цвет и другие детали оформления выбирает Developer. Checkbox и ссылка имеют раздельные действия. Пустые поля, ошибки полей и снятый checkbox не препятствуют чтению условий. Открытие не меняет отметку. Сценарии: AS-TERMS-01, AS-TERMS-02, AS-TERMS-14.

## REQ-TERMS-02 Возврат с отметкой ознакомления

<a id="req-terms-04"></a>
## REQ-TERMS-04 Сохранение черновика при переходе

Система должна сохранять черновик формы при текущем переходе к условиям и каждом из двух возвратов.

Сохранение означает равенство исходных и возвращённых значений даты, текста места, выбранного place_id с названием, строки времени и отметки неизвестности. Одинакового названия без выбранного place_id недостаточно. При незавершённом вводе не появляется фиктивный place_id или известное время. Отметка ознакомления изменяется отдельно по таблице T. Сохранение черновика через новую загрузку не добавляется.

Таблица D задаёт непересекающиеся классы черновика для обоих возвратов. Каждый сценарий выполняется двумя отдельными проходами: «Согласен» и «Вернуться к форме».

| ID строки | Состояние черновика перед открытием | Ожидаемый черновик после возврата | Сценарий |
| --- | --- | --- | --- |
| D1 | Дата валидна, место выбрано, время известно в HH:MM | Те же дата, place_id и название, строка HH:MM, неизвестность снята | AS-TERMS-08 |
| D2 | Дата валидна, место выбрано, время явно неизвестно | Те же дата, place_id и название, исходная строка времени, неизвестность выбрана | AS-TERMS-09 |
| D3 | Остальные состояния, включая пустые поля, незавершённый ввод и ошибки | Те же введённые значения и прежнее наличие выбранного place_id; автоматического исправления нет | AS-TERMS-10 |

В D1 отдельно проверяются 00:00 и 23:59; в D2 — пустая строка и ранее введённые 12:00; в D3 — полностью пустая форма, 12:6, текст места без выбора и изменённый черновик при прежней принятой карте. Это классы проверок, не новые правила расчёта.

<a id="req-terms-05"></a>
## REQ-TERMS-05 Изоляция ознакомления от построения

Система должна выполнять открытие условий и оба возврата без запуска построения карты.

Эти действия не отправляют POST /charts/natal и не меняют принятую карту как новый расчёт. Повторное нажатие возврата не запускает POST. Уже разрешённые bootstrap/current и recovery не превращаются в построение; контракт HTTP и журналов остаётся действующим. Сценарий: AS-TERMS-11 с позитивным контролем разрешённого явного построения по REQ-UI-03.

<a id="req-terms-07"></a>
## REQ-TERMS-07 Новая загрузка снимает отметку

Система должна показывать снятый checkbox после новой загрузки формы независимо от прежнего способа отметки.

Таблица L задаёт полный набор происхождений прежней отметки. Возвраты T1…T4 относятся к текущему переходу, а не к L.

| ID строки | Состояние до новой загрузки | Checkbox после новой загрузки | Сценарий |
| --- | --- | --- | --- |
| L1 | Снят или форма открывается впервые | снят | AS-TERMS-16 |
| L2 | Выбран вручную в форме | снят | AS-TERMS-17 |
| L3 | Выбран через «Согласен» | снят | AS-TERMS-18 |

Значение checkbox не добавляется в запрос построения, доменную команду, сессию, расчётный кэш или журнал подтверждений. Аккаунты, отметка версии условий и хранение факта ознакомления не вводятся. Восстановленная карта не восстанавливает отметку.

<a id="req-terms-08"></a>
## REQ-TERMS-08 Доступность ссылки и двух возвратов

Система должна предоставлять ссылку условий и оба возврата с доступными названиями, управлением клавиатурой и различимым фокусом.

Страница имеет заголовок «Условия использования сервиса». После открытия фокус находится на странице условий, после возврата — на видимом элементе формы. Конкретный элемент и способ навигации выбирает Developer. На ширине 360 px горизонтальная прокрутка страницы отсутствует; текст и обе кнопки доступны. Эффективная область нажатия — действующая граница REQ-UI-10, 44 × 44 CSS px; размер шрифта ссылки не задаёт размер области нажатия. Сценарий AS-TERMS-14.

## Сценарии Given / When / Then

Каждый нижеуказанный сценарий является заданием проверки, а не результатом прогона. Для всех переходов счётчик POST измеряется относительно завершённого исходного открытия формы; исходные bootstrap/current не вычитаются из другого сценария. «Нет POST» дополняется позитивным контролем явного построения. Наблюдаемость новых UI-действий — страница, значения формы, focus и сетевой счётчик. Новый серверный журнал подтверждений не вводится. Если выполняется действующий business request, сохраняются X-Request-ID, парные http_message и terminal по HTTP-контракту; статические ресурсы не получают вымышленные business events.

<a id="as-terms-01"></a>
### AS-TERMS-01 — Ссылка и страница

REQ: REQ-TERMS-01, REQ-TERMS-08.
Given открыта форма, checkbox снят, исходные чтения завершены.
When пользователь нажимает текстовую ссылку под checkbox.
Then видна отдельная страница с заданным заголовком и текстом; доступны «Согласен» в конце и «Вернуться к форме»; checkbox до возврата не изменён; POST отсутствует.
Проверка: расположение, computed шрифт относительно пояснения неизвестного времени, состояние checkbox и счётчик POST. Контроль: нажатие самого checkbox меняет отметку и оставляет форму.

<a id="as-terms-02"></a>
### AS-TERMS-02 — Чтение без валидной формы

REQ: REQ-TERMS-01, REQ-TERMS-04.
Given форма пустая; отдельный проход — форма с ошибками даты, времени и места.
When пользователь открывает условия и нажимает «Вернуться к форме».
Then страница доступна в обоих проходах; исходные значения формы и снятый checkbox сохранены; валидация построения не закрывает доступ к тексту; POST отсутствует.
Контроль: явное построение при тех же ошибках заблокировано, исправление полей и отметка допускают построение по REQ-UI-03.

<a id="as-terms-03"></a>
### AS-TERMS-03 — T1, согласен при снятой отметке

REQ: REQ-TERMS-02, REQ-TERMS-04, REQ-TERMS-05.
Given checkbox снят, записан черновик формы, условия открыты из формы.
When пользователь нажимает «Согласен».
Then форма видна, checkbox выбран, черновик совпадает с исходным, POST отсутствует.
Контроль: перед действием checkbox действительно снят; последующее отдельное построение с валидными полями отправляет один POST.

<a id="as-terms-04"></a>

When пользователь нажимает «Согласен».
Then форма видна с выбранным checkbox и прежним черновиком; POST отсутствует.
Контроль: повторный проход с исходно снятым checkbox также выбирает отметку по T1.

<a id="as-terms-05"></a>
### AS-TERMS-05 — T3, возврат при снятой отметке

REQ: REQ-TERMS-03, REQ-TERMS-04, REQ-TERMS-05.
Given checkbox снят, условия открыты из заполненной формы.
When пользователь нажимает «Вернуться к форме».
Then форма видна, checkbox снят, черновик сохранён, POST отсутствует; отдельная попытка построения требует отметку.
Контроль: отдельный проход T1 выбирает checkbox и допускает последующее явное построение при валидных полях.

<a id="as-terms-06"></a>
### AS-TERMS-06 — T4, возврат при выбранной отметке

REQ: REQ-TERMS-03, REQ-TERMS-04, REQ-TERMS-05.
Given checkbox выбран, условия открыты из заполненной формы.
When пользователь нажимает «Вернуться к форме».
Then форма видна с прежним черновиком и выбранным checkbox; POST отсутствует.
Контроль: отдельный проход T3 сохраняет снятую отметку, а не безусловно выбирает checkbox.

<a id="as-terms-07"></a>
### AS-TERMS-07 — Повторный переход после снятия отметки

REQ: REQ-TERMS-02, REQ-TERMS-03, REQ-TERMS-04.
Given пользователь вернулся через «Согласен», затем вручную снял checkbox.
When пользователь снова открывает условия и нажимает «Вернуться к форме».
Then checkbox остаётся снятым; черновик совпадает с последним вводом; прежнее «Согласен» не восстанавливает отметку.
Контроль: следующий новый проход с «Согласен» снова выбирает checkbox; ни один возврат не отправляет POST.

<a id="as-terms-08"></a>
### AS-TERMS-08 — D1, известное время

REQ: REQ-TERMS-04.
Given введена валидная дата, выбрано место с place_id и известное время; отдельные проходы 00:00, 12:00, 23:59.
When пользователь открывает условия и возвращается каждым из двух способов в отдельных проходах.
Then дата, place_id, название и строка времени равны исходным; неизвестность снята; checkbox соответствует T1…T4.
Контроль: последующее явное построение отправляет исходные birth_date, HH:MM, place_id, а не null или текст названия вместо ID.

### AS-TERMS-11 — Изоляция от построения и повторное действие

REQ: REQ-TERMS-05, REQ-UI-03.
Given валидная форма, известная исходная принятая карта либо empty в двух проходах, счётчик POST равен нулю.
When пользователь открывает условия, возвращается каждой кнопкой в отдельных проходах и повторяет активацию возврата до завершения перехода.
Then POST остаётся равен нулю, принятие новой карты от этих действий отсутствует, возвращённый черновик сохранён.
Контроль: после возвращения с выбранным checkbox отдельное явное построение отправляет ровно один POST и показывает фактический результат; дальнейшая повторная отправка во время ожидания не добавляет второй POST.

### AS-TERMS-13 — G1…G4 и R1…R3, граница явного построения

REQ: REQ-UI-03, REQ-TERMS-02, REQ-TERMS-07.
Given клиент допускает построение по HTTP/recovery-контракту.
When Tester отдельно воспроизводит каждую строку G1…G4.
Then G1 не добавляет POST при каждом сочетании checkbox/валидности; G2 не добавляет POST при обоих состояниях валидности; G3 показывает ошибки полей без POST; G4 отправляет один POST после ручной отметки и после «Согласен» в отдельных проходах.
Given G4 выполнился.
When поступает каждый класс ответа R1…R3 в отдельном проходе.
Then R1 показывает committed факты; R2 читает current и показывает фактический ответ; R3 сохраняет черновик и выполняет только разрешённые REQ-UI-09 действия.
Контроль: поле checkbox и новые поля подтверждения отсутствуют в POST; валидный G4 является позитивным контролем запретов G1…G3. Серверные ошибки и recovery проверяются существующими AS-UI без новых кодов ошибок.

### AS-TERMS-14 — Клавиатура, фокус и узкий экран

Контроль: текстовая ссылка открывает условия без переключения checkbox, сам checkbox переключает отметку без открытия условий; область нажатия проверяется доверенным указателем и фактическим получателем, не одним bounding box.
