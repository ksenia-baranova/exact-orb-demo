# ADR-0016. Натал — базовое состояние; транзит — производный расчёт

Дата: 2026-08-25. Ревизия: 2026-08-25 — состояние вида карты приведено
к структуре `SessionProfile`; зафиксировано ограничение для космограммы.
Ревизия: 2026-09-04 — в MVP сессия хранит **одну** карту: `derived_chart`,
`active_view` и команда `SetActiveView` отсутствуют вместе с транзитами;
`SessionProfile` переименован в `SessionState`. Сужение временное, условие
снятия названо явно.
Статус: принято.

## Контекст

Транзиты требуют базовой натальной карты — это отражено в разделении `tools[]`
и `topics[]` (ADR-0004). На UI возникает вопрос, заменять ли карту при переходе
к транзитам. Замена потеряла бы исходную модель субъекта.

## Решение

`NatalChart` или космограмма является base chart сессии. Транзит производен
и базу не мутирует:

```
BaseChart + TransitMoment + TransitLocation? → calculate_transit() → TransitChart
```

Состояние вида живёт в `SessionState` (ADR-0009): `base_chart`,
`derived_chart`, `active_view`. Каждая ссылка хранит `ChartSpec`, а не только
ключ (ADR-0017), и несёт `state_version` (ADR-0014). Переключение вида —
явная операция `SetActiveView`.

**Сужение MVP.** Транзиты в первый срез не входят, поэтому `derived_chart`,
`active_view` и `SetActiveView` в нём **отсутствуют**, а не присутствуют
с постоянным значением: поле, которое всегда равно `base`, — это поле,
которое некому проверять, и первая же ошибка в нём обнаружится только
вместе с транзитами. Сессия хранит одну карту.

Само решение этим не отменяется: оно продолжает описывать целевую модель.
`SetActiveView` нужна не для рисования, а потому что `active_view`
определяет, **по какой карте отвечает интерпретация** — при двух картах
в сессии вопрос «расскажи про Марс» неоднозначен.

**Условие снятия сужения:** появление транзитов в срезе. Вместе с ними
возвращаются все три сущности, а также пересмотр потолков нагрузки
(ADR-0013) — окно ±12 месяцев считается 0.51 с против 16 мс у натала.

Наименование единообразно с ADR-0001: операция `calculate_transit()`, результат
`TransitChart`; промежуточное `TransitCalculation` не вводится.

**Ограничение при `chart_kind = cosmogram`.** `calculate_transit()` требует
`natal.cusps` и `natal.angles`, которых у космограммы нет (ADR-0008). Значит
`active_view = derived` при базовой космограмме **недоступен**, и UI обязан
блокировать переход с объяснением, а не показывать ошибку расчёта. Ограничение
снимается вместе с реализацией пути без углов.

## Альтернативы

Заменять натал транзитом в сессии — отвергнуто: транзит не новая идентичность
субъекта. Хранить только transit result — отвергнуто: неявная связь и трудности
повторных сценариев.

## Последствия

- Изменение данных рождения и изменение момента транзита — разные операции.
- Дату транзита можно менять без пересчёта натала.
- Кэш натала переиспользуется для множества транзитных моментов.
- `tools = [natal, transit]` не означает `topics = [natal, transit]`.
