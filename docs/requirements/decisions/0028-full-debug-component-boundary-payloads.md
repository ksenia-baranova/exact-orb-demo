# ADR-0028. Полные сообщения всех компонентных границ только в DEBUG

Дата: 2026-09-11.
**Статус: принято.**

Заменяет ADR-0026. Восстанавливает исходное требование ADR-0025 о полном
входном и выходном сообщении каждой реализованной компонентной границы и
сохраняет добавленный ADR-0026 единый envelope с `calculation_key`, `status`,
`payload_mode` и `message_type`.

## Контекст

ADR-0026 заменил полные внутренние результаты на `NatalChartSummary`,
`CalculationResultSummary` и `ChartArtifactSummary`, оставив полный результат
только на выходе handler. Это сократило дублирование больших JSON, но скрыло
именно те поля, сравнение которых нужно для поиска рассинхронизации между
разрешением рождения, спецификацией, движком, артефактом и итоговым delta.

Проблема множественных источников истины была обнаружена только после печати
полного `BuildNatalSuccess`. При summary-режиме нельзя установить, на какой
границе изменились UTC-время, координаты или вложенный блок карты. Для
локальной диагностики полезность полного сквозного следа выше стоимости
повторной сериализации.

## Решение

В локальном режиме `DEBUG` каждая реализованная граница Build Natal пишет
полное входное сообщение и полный фактический выход:

| Граница | Полный успешный выход |
|---|---|
| `BuildNatalHandler.handle` | `BuildNatalSuccess` |
| `BirthDataResolver.resolve` | полный resolution outcome |
| `ChartArtifactResolver.ensure_chart` | публичный `ChartArtifact` |
| `EngineService.calculate` | `CalculationResult` |
| `calculate_natal` | `NatalChart` |

Типизированные short-circuit outcomes handler и birth resolver также
записываются полностью как фактический выход соответствующей границы.

Формат события:

```text
component_message direction=<in|out> operation=<operation>
                  run_id=<id|-> calculation_key=<full key|->
                  status=<ok|error> payload_mode=<full|error>
                  message_type=<type> message=<single-line JSON>
```

Для успешного входа или выхода `payload_mode=full`, а `message` содержит весь
объект без summary и усечения. Для исключения `payload_mode=error`, а объект
ошибки содержит тип, сообщение и доступные `code`/`run_id`.

`ChartArtifactResolver` имеет внутренний технический результат
`_EnsuredChart(artifact, cache_outcome)`, но наружу границы проектируется
именно полный публичный `ChartArtifact`. `cache_outcome` остаётся в отдельных
технических событиях кэша и не меняет публичный контракт.

`calculation_key` появляется отдельным полем envelope там, где уже вычислен.
`run_id` связывает один прикладной проход. У чистой функции `calculate_natal`
остаётся `run_id=-`: диагностический контекст не добавляется в вычислительный
API и не передаётся скрытым mutable-состоянием.

Отдельный UUID результата карты не вводится: попытку идентифицирует `run_id`,
а канонический расчёт — `calculation_key`. Engine API ключ не получает и
связывается с artifact boundary только по `run_id`.

В INFO/WARNING остаются компактные операционные события. Полные сообщения
пишутся только в DEBUG; если соответствующий logger не допускает DEBUG,
payload и result projector не вычисляются, JSON не сериализуется.
Отдельный logging-флаг не вводится: режим определяется effective log level.

## Граница эксплуатации

Полный DEBUG-журнал намеренно содержит дату и время рождения, место,
координаты, timezone-данные, полные результаты расчёта, предупреждения и
технические сведения. Это разрешено только для текущего локального
диагностического режима: без полных данных нельзя надёжно локализовать
рассинхронизацию компонентных сообщений.

Уровень `DEBUG` по умолчанию в локальном CLI делает риск фактическим, а не
теоретическим. До публичного развёртывания обязательны отдельное решение о
выключении, маскировании или защищённой маршрутизации этих событий, политика
retention и контроль доступа. До выполнения этого условия проект не считается
пригодным для публичной обработки персональных данных.

ADR-0023 о Research Corpus и consent-flow не меняется: диагностический журнал
не становится исследовательским корпусом и не получает его разрешений.

## Альтернативы

**Оставить summary внутренних результатов** — отвергнуто: summary не позволяет
сравнить поля модели и найти момент рассинхронизации.

**Писать полный результат только один раз** — отвергнуто: итог показывает
противоречие, но не ответственную границу.

**Включать полные сообщения на INFO** — отвергнуто: это смешивает
диагностический payload с операционным журналом и делает фильтрацию режима
невозможной.

**Динамически усекать большие значения** — отвергнуто: лог перестаёт быть
полным и его форма зависит от конкретных данных.

**Добавить отдельный флаг полного payload** — отвергнуто: он создаёт вторую
независимую настройку поверх log level и допускает неочевидные комбинации;
локальный диагностический контракт однозначно привязан к effective DEBUG.

## Последствия

- все пять границ дают сопоставимый полный сквозной след;
- исчезают `NatalChartSummary`, `CalculationResultSummary`,
  `ChartArtifactSummary` и режим `payload_mode=summary`;
- одна карта может сериализоваться несколько раз на cache miss и как минимум
  на artifact/application границах на cache hit;
- единый envelope ADR-0026 сохранён и пригоден для поиска по `run_id`, полному
  `calculation_key`, направлению, статусу и типу сообщения;
- ниже DEBUG нет стоимости сериализации полного payload и вычисления logging-
  проекций;
- объём локальных логов и скорость ротации увеличиваются;
- privacy-hardening остаётся обязательным блокером публичного развёртывания.
