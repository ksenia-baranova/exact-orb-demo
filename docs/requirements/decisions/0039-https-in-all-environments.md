# ADR-0039. HTTPS во всех окружениях; `Secure` cookie без переключателя

Дата: 2026-09-24.
**Статус: принято.**

**Восстановлено 2026-09-29:** исходный файл найден в commit `cf16d41`
через reflog ветки change и восстановлен без смысловых изменений. Сам commit
не достижим из текущих branch refs.

Дополняет ADR-0009 в части cookie: требование `Secure` распространяется на
все окружения, включая локальную разработку и автоматические тесты.
Рабочий вариант спецификации HTTP API (M1-6) — флаг окружения, снимающий
`Secure` вне production, — этим решением отвергается.

## Контекст

ADR-0009 идентифицирует анонимную сессию cookie с атрибутами `HttpOnly`,
`Secure`, `SameSite`; строка M1-6 в roadmap повторяет это требование. Как
оно выполняется там, где нет production TLS, не определено ни одним
документом: HTTP-слоя до M1-6 в коде нет, а reverse proxy и TLS на сервере
появляются только в M1-13.

Браузер отправляет `Secure` cookie только по HTTPS. Для `http://localhost`
есть исключение, но оно не одинаково в разных браузерах (Safari исторически
его не делал) и не действует для любого не-loopback адреса: телефона в
локальной сети, имени контейнера, IP рабочей машины. Тестовый клиент httpx
тоже не отправляет `Secure` cookie на `http://`-адрес.

Целевая форма развёртывания (`architecture/deployment.md`) — контейнер
приложения за reverse proxy на одном хосте. TLS завершается на proxy, а
приложение получает обычный HTTP и заголовки `X-Forwarded-*`. От правильного
разбора этих заголовков зависят схема запроса и источник IP для admission.

Рассматривались три способа: флаг, снимающий `Secure` вне production;
`Secure` всегда при работе локально через `http://localhost`; HTTPS
локально.

## Решение

**`Secure` ставится всегда.** В коде и конфигурации нет параметра, который
его снимает или ослабляет. Проверка атрибутов cookie не зависит от
окружения.

**Браузер обращается к приложению только по HTTPS, в том числе локально.**
Локальная схема повторяет серверную топологию: reverse proxy завершает TLS
и проксирует запросы на приложение. Сертификат выпускается локальным CA,
которому доверяет рабочая машина (например, mkcert). Приложение само TLS
не поднимает.

**Принудительность обеспечивается топологией.** Приложение слушает только
loopback или внутреннюю сеть контейнера; единственная точка входа для
браузера — proxy. Plain HTTP на proxy отвечает перенаправлением на HTTPS.
Прямое обращение к порту приложения по `http://localhost` не является
поддерживаемым режимом: то, что оно может сработать в отдельном браузере,
не гарантируется и не проверяется.

**Доверие к proxy проверяется локально.** Приложение учитывает
`X-Forwarded-Proto` и `X-Forwarded-For` только от сконфигурированного
доверенного proxy. Механизм и параметры определяет спецификация HTTP API;
локальная схема обязана проходить через тот же путь, что и серверная.

**Автоматические тесты не требуют настоящего TLS.** In-process ASGI-клиент
работает с `base_url="https://testserver"`. Тесты проверяют, что
`Set-Cookie` сессии содержит `HttpOnly`, `Secure` и `SameSite`.

## Альтернативы

**Флаг окружения, снимающий `Secure` вне production** — отвергнуто. Ошибка
конфигурации (флаг, попавший на стенд) тихо ослабляет защиту и ничего не
роняет. Локальная разработка и тесты идут в конфигурации, которой нет в
production, поэтому связки вроде «`SameSite=None` требует `Secure`» не
проверяются. Префикс `__Host-`, требующий `Secure`, стал бы невозможен в
части окружений, и имя cookie зависело бы от окружения.

**`Secure` всегда, локально `http://localhost` без TLS** — отвергнуто как
поддерживаемый режим. Опирается на браузерное исключение для localhost,
которое не одинаково в разных браузерах и не работает для не-loopback
адресов, и не проверяет путь через proxy и `X-Forwarded-*` до деплоя.

**TLS непосредственно в uvicorn (`--ssl-keyfile`, `--ssl-certfile`)** —
отвергнуто как основная схема: даёт HTTPS, но не повторяет топологию с
proxy, поэтому разбор `X-Forwarded-*` и определение IP локально не
проверяются.

## Последствия

- Разовая стоимость для разработчика: установить локальный CA и доверить
  его на рабочей машине. Проверка с телефона требует установить CA и на
  телефон.
- Конфигурация локального proxy и инструкция запуска входят в M1-6,
  вместе с появлением HTTP-слоя.
- Определение схемы запроса и источника IP за доверенным proxy
  проверяется локально до деплоя M1-13.
- Префикс `__Host-` для session cookie допустим одинаково во всех
  окружениях; имя cookie и значение `SameSite` определяет спецификация
  HTTP API.
- HSTS включается только на сервере (M1-13), не на локальном proxy: HSTS
  для localhost закрепляется в браузере и мешает другим локальным проектам.
- ADR-0009 не меняется: это решение конкретизирует, как его требование
  `Secure` выполняется вне production.
