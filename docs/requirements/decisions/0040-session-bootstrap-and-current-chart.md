# ADR-0040. Bootstrap сессии отделён от чтения текущей карты

Дата: 2026-09-24.
**Статус: принято; восстановленная ревизия согласована Lead 2026-09-30.**

**Ревизия: 2026-09-29 —** принятый 2026-09-24 вариант C с отдельным
`GET /charts/current` через `ApplicationOrchestrator`/`ensure_chart` пересмотрен
в вариант D после ADR-0041: bootstrap остаётся без карты, а current GET читает
уже сохранённый `StoredChart` через `ContextService.load` и чистый
`application/session_view`, без resolver и повторного расчёта.

**Восстановлено 2026-09-29:** запись отсутствовала в восстановленной ветке, а
её номер ошибочно заняло более позднее решение от 2026-09-26. Позднее решение
о хранении карты перенумеровано в ADR-0041; его предметное решение сохранено.

Точный исторический файл ADR-0040 не найден среди branch refs, reflog и 384
недостижимых blob, перечисленных `git fsck`. В них сохранились только
конфликтующий StoredChart ADR и draft HTTP/UI. Реестр от 2026-09-24 сохраняет
исходный вариант C; текущий текст явно отделяет его от ревизии D. Lead
согласовал восстановленную формулировку 2026-09-30.

Дополняет ADR-0006 и ADR-0009 в части HTTP-жизненного цикла анонимной сессии.
ADR-0041 определяет, где хранится построенная карта; эта запись определяет,
какой HTTP endpoint читает сохранённое представление.

## Контекст

При открытии приложения transport должен решить две разные задачи:

1. убедиться, что у браузера есть живая анонимная сессия, и при необходимости
   создать новую;
2. прочитать текущее предметное состояние и показать сохранённую карту.

Если `POST /session/bootstrap` одновременно возвращает полную карту, session
lifecycle связывается с большим и изменяемым публичным `ChartDTO`. Обновление
карты после неопределённого результата commit, возврат вкладки в foreground и
обычный refresh вынуждены повторять bootstrap, хотя новую сессию создавать не
нужно. Ошибки создания/восстановления сессии смешиваются с ошибками projector.

На 2026-09-24 был выбран вариант C: bootstrap только сессии и отдельный
current GET через `ApplicationOrchestrator`/`ensure_chart`. После принятия
ADR-0041 появилась более узкая операция чтения уже сохранённого артефакта,
поэтому 2026-09-29 transport boundary пересмотрена в вариант D.

## Решение

**Вариант D: bootstrap не возвращает карту.**

`POST /session/bootstrap` отвечает только за cookie и liveness сессии. Он
создаёт новую запись или выполняет обязательный `ContextService.load` для
живой cookie и возвращает компактный `SessionBootstrapDTO` со
`state_version`. Он не вызывает `application/session_view`, resolver, cache,
engine или `ApplicationOrchestrator`.

**Текущая карта читается отдельным `GET /charts/current`.** Endpoint требует
пригодную session cookie, выполняет `ContextService.load`, передаёт snapshot в
чистый `application/session_view` и возвращает `empty`, `chart_ready` либо
`chart_unavailable`. Он не создаёт сессию и не выполняет расчёт.

После первого bootstrap и при повторном открытии страницы клиент вызывает
`GET /charts/current`. После `RESULT_SUPERSEDED`, `AlreadyApplied` без
публикации артефакта или неопределённого `STATE_COMMIT_FAILED` клиент сначала
читает current chart. Новый `POST /charts/natal` выполняется только по явному
действию пользователя.

Bootstrap и current-chart load оба являются read-and-renew для уже живой
сессии. Два последовательных touch при открытии страницы допустимы: они не
меняют `state_version`, не запускают расчёт и сохраняют единую ответственность
endpoint. Оптимизировать их в один скрытый transport вызов нельзя, если это
снова объединяет публичные контракты.

## Альтернативы

**Исходный вариант C: current GET через Orchestrator/`ensure_chart`** — заменён
ревизией 2026-09-29. После ADR-0041 restore должен читать persisted artifact;
запуск resolver/cache/engine на обычном refresh создавал бы новый расчётный
путь и смешивал чтение с ensure/rebuild.

**Bootstrap возвращает `SessionViewDTO` с картой** — отвергнуто. Увеличивает
ответ обязательной lifecycle-операции, связывает её с projector и не даёт
отдельной операции сверки текущей карты после конкурентного либо
неопределённого commit.

**Restore через `ApplicationOrchestrator`** — отвергнуто. ADR-0006 разрешает
transport напрямую вызвать `ContextService` для bootstrap/restore; здесь нет
application-команды и мутации предметного состояния.

**Клиент хранит последнюю карту и не читает её с сервера** — отвергнуто.
Сессия является источником текущей карты, должна переживать restart и должна
корректно отражать изменения из другой вкладки.

## Последствия

- Публичный M1-6 содержит четыре бизнес-endpoint: bootstrap, current chart,
  place search и build natal.
- `SessionBootstrapDTO` и `SessionViewDTO` имеют разные назначения и схемы.
- Ошибка `StateReadFailed` не превращается в создание новой сессии ни в одном
  endpoint.
- `GET /charts/current` не расходует build quota и не занимает calculation
  capacity.
- `Cache-Control: no-store` обязателен для обоих session-ответов.
- HTTP sequence diagrams содержат отдельные потоки bootstrap и current chart.
