## Подробности контролируемых переходов

**5xx / damaged DTO.** Raw502 → held bootstrap/current; failed current503 STATE_READ_FAILED оставляет check_failed и запрещает build. Safe repeat получает прежнюю карту, явная ручная отправка после gate успешно строит. Typed INTERNAL_FAILURE500 после настоящего commit проходит bootstrap/current и находит committed2005; raw504 без ErrorDTO не становится BUILD_TIMEOUT. Malformed successful POST/current с `points:null` не вызывает TypeError, не стирает confirmed facts и не разрешает POST до safe read. Browser console errors после проверок — пустой список; шире malformed shapes проверены параметризацией Node suite.

**Stale / unavailable.** Реальная смена Selena method меняет CalculationVersion. Matching stale identity после before-status abort остаётся «Свежий результат не подтверждён», не matched. Exact fresh identity — positive matched control. Damaged SQLite payload выдаёт настоящий chart_unavailable с birth, без таблиц; explicit rebuild восстанавливает факты. Ни один путь не объявляет отсутствие карты на основании bootstrap version.

**Late / manual.** После потери original2000 browser выполняет только bootstrap/current; original intent остаётся видимым, draft2001 отдельный. `/wait` подтверждает waiting второго POST, `/release` пропускает первый до actual commit, второй synthetic superseded требует GET173 и показывает именно2000. Дополнительно реальный SQLite CAS covered by test_concurrent_sqlite_intents_map_committed_already_applied_and_superseded. Abort_after_forward2002 доказывает recovery настоящего commit с потерянным ответом; abort-before-forward2003 плюс manual positive доказывает отказ без скрытого POST. Gate в proxy удерживает передачу запроса, не выдаётся за app-level protected commit; отмена/shield приложения доказаны существующими real lifecycle tests.

### AS-UI-16: историческое ограничение IAB, 2026-10-08

A имеет draft2010-01-01 и confirmed map2009. B с общей cookie реально коммитит2012 (wire213), повтор B после открытия Browser пользователем реально коммитит2013 (wire250). A не отправляет draft сам. Но getTab только привязывает handle; после close B selected=A, document всё время остаётся `hidden:false / visibilityState:'visible'`. Browser visibility.set(false) даёт presented:false при том же visible document; set(true) не создаёт перехода. `open_in_codex` продолжает возвращать queued даже после ответа пользователя «Открыто».
