# UI/UX

**Статус: черновик целевого дизайна V2, не реализован.** Дата: 2026-09-25.

Раздел описывает, каким должен стать интерфейс exact-orb: ввод данных рождения,
экран готовой карты, подробная карта и (в M2) персональный разбор. Эти экраны
есть в демонстрационном HTML-прототипе, но ещё не реализованы в приложении. Если
описание здесь расходится с кодом приложения, верен код;
если расходится с ADR или требованиями компонентов, верны они. Тексты получены из
приложенного архива. Упомянутые в них будущие HTTP-контракты и решения остаются
предложениями до согласования в действующих требованиях и ADR.

## Как читать рендеры

Из рендеров берутся **только композиция, палитра и ритм**. Ни одно число, положение
планеты, дом, аспект, процент или подпись с рендера не является данными и не может
служить эталоном для тестов.

Исходные Р1–Р4 содержат внутренние противоречия (например, положение Солнца не
согласовано с асцендентом, а MC на разных рендерах в разных знаках). Известные
расхождения приведены в `render_review.md`.

Демо-данные на Р1–Р4 («Анна · 02.09.1990 · 14:30 · Москва») и Р5
(«Кировск · 05.09.1988 · 04:40») — не значения по умолчанию и не тест
истинности расчёта.

## Связанные документы

- Упомянутая в приложенных текстах спецификация HTTP API (черновик 2026-09-25)
  отдельно не приложена; `POST /session/bootstrap`, `POST /charts/natal` и
  `GET /places` здесь рассматриваются как целевые интерфейсы.
- ADR-0006 — bootstrap идёт мимо Orchestrator.
- ADR-0008 — космограмма при неизвестном времени.
- ADR-0029…0032 — идентификаторы точек, ось узлов, конфигурации, аспекты при
  неизвестном времени.
- ADR-0039 — HTTPS во всех окружениях.
- ADR-0040 в репозитории пока отсутствует; вариант D описан как предложение в
  `decisions.md`.
