# Решения по интерфейсу

Дата: 2026-09-25. Реестр предложений и открытых решений по UI до их переноса в
ADR и требования компонентов. Описанное ниже не утверждает новые архитектурные
контракты. ADR-0040 в текущем репозитории отсутствует.

## 1. Предложения из приложенного проекта

### 1.1. Восстановление сессии — вариант D

В приложенном проекте предложено, чтобы `POST /session/bootstrap` сразу отдавал
сохранённую карту без отдельного `GET /charts/current`. Окончательное решение
требует ADR и синхронизации действующих требований.

Следствия:

1. После рестарта сервера карта не пересчитывается. Bootstrap читает сохранённую
   карту, не трогает движок и кэш расчётов, не занимает слот конкурентности и не
   расходует лимит построений.
2. Хранится `ChartArtifact` через строгий codec. `ChartDTO` собирается при чтении
   в `application/session_view`, поэтому смена публичного DTO не требует миграции
   хранилища.
3. `chart_stale` — сохранённая карта посчитана другой `CalculationVersion`.
   Интерфейс показывает её с пометкой; пересчёт только по явному действию
   человека через `POST /charts/natal`, с расходом лимита.
4. `chart_unavailable` — сохранённая карта не читается или не проходит codec.
   `birth_input` сохранён; интерфейс предлагает пересчитать без повторного ввода.
5. ADR-0006 не меняется: bootstrap идёт transport → `ContextService`, без
   Orchestrator.

### 1.2. Чат — M2

Интерпретация и диалоги относятся к M2. Первая вертикаль M1: Э1–Э7.

### 1.3. Мобильная версия проектируется вместе с desktop

Мобильные макеты утверждаются до кода. Основные правила — в `requirements.md`, §9.

## 3. Предложение `ChartDTO`

Один объект в `SessionViewDTO.chart` и в ответе `POST /charts/natal`. Собирается
из `ChartArtifact` по белому списку полей; автодамп модели запрещён.

```json
{
  "chart_identity": "…",
  "kind": "natal",
  "time_is_unknown": false,
  "birth": {
    "local_date": "1990-09-02",
    "local_time": "14:30",
    "place": { "place_id": "524901", "display_name": "Москва", "admin1_name": "Москва", "country_code": "RU" },
    "utc_offset": "+04:00",
    "tz_id": "Europe/Moscow"
  },
  "settings": { "zodiac": "tropical", "house_system": "placidus" },
  "points": [
    { "id": "sun", "longitude": 162.5, "sign": "virgo", "degree": 12, "minute": 30, "house": 3, "retrograde": false }
  ],
  "angles": {
    "asc": { "longitude": 100.0, "sign": "cancer", "degree": 10, "minute": 0 },
    "mc": {}, "dsc": {}, "ic": {}
  },
  "houses": [ { "number": 1, "cusp_longitude": 100.0, "sign": "cancer", "degree": 10, "minute": 0 } ],
  "aspects": [
    { "a": "sun", "b": "neptune", "type": "trine", "orb": 0.4, "category": "exact", "time_dependent": false }
  ]
}
```

| Поле | Правило | Почему |
|---|---|---|
| `chart_identity` | Меняется только когда меняется сама карта | Отличает новую карту от нового `state_version`; позже уходит в `expected_chart_identity` интерпретации |
| `kind`, `time_is_unknown` | `cosmogram` и `true` при `birth_time = null` (ADR-0008) | Интерфейс не выводит неизвестность времени из других полей |
| `birth.utc_offset`, `tz_id` | Фактически применённые движком | Строка «UTC+4 на дату рождения» без угадывания в браузере |
| `points[].id` | Канонические идентификаторы (ADR-0029); узлы — по ADR-0030 | Одно пространство имён для круга, таблиц и аспектов |
| `sign`, `degree`, `minute` | Считает и округляет движок | Фронтенд не пересчитывает знаки; округление на границе знака в одном месте |
| `house`, `angles`, `houses` | `null` при неизвестном времени, а не отсутствие поля | Контракт проверяется тестом |
| `aspects[].category` | Категория движка `exact / working / background` | «Точный» = `exact`; порог не живёт во фронтенде |
| `aspects[].time_dependent` | Семантика ADR-0032 для лунных аспектов без времени | Интерфейс рисует такие аспекты иначе |
| DSC и IC | Отдаются явно | Фронтенд ничего не пересчитывает |

Стихий и «качеств» в DTO нет до утверждённой методики.

## 4. Замечания к спецификации HTTP API

| № | Замечание | Исправление |
|---|---|---|
| 1 | `ChartDTO` указан как `"…"` | Описать по разделу 3 |
| 2 | `chart_stale` не определён | Определение из 1.1 |
| 3 | `chart_unavailable` не описан для интерфейса | Пересчёт по сохранённому `birth_input` |
| 4 | `canonical_place` — одна строка | Объект места той же формы, что подсказка `GET /places` |
| 5 | CSRF требует `Content-Type: application/json`, у bootstrap «тела нет» | Тело `{}` с этим заголовком |
| 6 | Формат `issues` не задан | См. открытое решение №8 |
| 7 | После 409 по сессии bootstrap даёт пустую сессию | Форма сохраняет значения; повтор только по нажатию |
| 8 | `RESULT_SUPERSEDED` описан как ошибка | Интерфейс делает bootstrap и показывает актуальную карту с пояснением |
| 9 | Повторная отправка увеличивает `state_version` | Интерфейс опирается на `chart_identity` |
| 10 | Язык `user_message` не задан | См. открытое решение №7 |
| 11 | У `GET /places` свой формат ошибок | Оставить; фронтенду нужны два разборщика |
| 12 | Код отказа создания сессии не выбран | Новый вид в `failure_policy`, например `session_create_failed` |
