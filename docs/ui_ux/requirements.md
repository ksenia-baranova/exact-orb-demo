# Требования к интерфейсу для кодинг-агента

Статус: проект требований. Версия: 2026-09-25, с исправлениями по разбору рендеров
и спецификации HTTP API. Дизайн: целевая версия V2, не реализована.
Язык интерфейса: русский.

Документ описывает ожидаемый результат и приёмку. Он не разрешает менять
архитектурные контракты backend. Открытые вопросы — в `decisions.md`; агент их
не решает сам.

## 1. Что сделать

Адаптивный интерфейс, в котором человек вводит данные рождения, получает
рассчитанную натальную карту и может открыть её подробности. Круг карты — встроенный
интерактивный SVG-компонент на данных существующего расчётного движка.

**Первая вертикаль (M1):** ввод → расчёт → «Карта готова» → подробная карта, плюс
состояния сессии (Э1–Э7). Чат (Э8, Э9) — M2, после блока интерпретации.

Перед реализацией агент:

1. фиксирует обнаруженный стек фронтенда, существующие API и типы;
2. сверяет фактический ответ API с `ChartDTO` из `decisions.md` и описывает адаптер;
3. показывает перечень экранов и состояний;
4. выносит в таблицу решений всё, что не закрыто в `decisions.md`.

Астрологические допущения не выбираются молча, рассчитанные значения не
подменяются примерами из рендеров. Каждый экран сверяется с его рендером и
мобильным макетом. После реализации — скриншоты desktop и mobile и перечень
проверенных сценариев простым языком.

Документ велик для одного промта. Работа делится на ветки по разделу 12, у каждой —
свои Allowed/Forbidden files и decision gate.

## 2. Рендеры и экраны

Нумерация рендеров (Р1–Р5) и экранов (Э1–Э9) — в `README.md`. Из рендеров берутся
только композиция, палитра и ритм; ошибки рендеров перечислены в `render_review.md`.

Р3 («Символы карты») — справочник, а не пользовательский экран: единые SVG-символы
планет, знаков, углов, аспектов и стихий используются во всех экранах.

Э7 (подробная карта) имеет отдельный мобильный макет. Desktop-вариант Р5
экспортирован из `web-prototype.html`. В обоих случаях значения демонстрационные.

## 3. Визуальные правила

| Назначение | Цвет |
|---|---|
| Фон | `#080706` |
| Карточки | `#15110E` |
| Основной акцент, жёлтое золото | `#F0CD73` |
| Второй акцент, тёмное золото | `#E0B357` |
| Напряжённые аспекты, красное золото | `#D07B58` |
| Вторичный текст | `#B8AA97` |

- Цвета, размеры, типографика и отступы — в общих токенах.
- Сохранить впечатление рендеров: много воздуха, тонкие линии, спокойные карточки,
  заметные основные действия. Рендер страницы не вставляется картинкой.
- Шрифт проверяется на русских буквах и астрологических символах в целевых браузерах;
  при неустойчивом отображении — собственные SVG-символы.
- Цвет не единственный способ различить аспект или состояние: у напряжённых аспектов
  пунктир, у квинконса точки.
- Проверяются контраст текста и состояний кнопок, видимый фокус, читаемость на телефоне.

## 4. Ввод данных (Э1, Э2)

### Содержимое и поведение

- Заголовок «Ваша карта начинается здесь»; пояснение: для начала нужны дата и город
  рождения, время повышает точность.
- Поля в порядке: дата (обязательно), место (обязательно), время (необязательно),
  имя (необязательно; судьба поля — `decisions.md`, №5).
- Дата — текстовое поле с маской и цифровой клавиатурой на телефоне.
- Место — подсказки `GET /places` по мере ввода. Выбор сохраняет `place_id`, а не
  строку. Одноимённые города различаются регионом и страной
  (`admin1_name`, `country_code`). Управление мышью, стрелками и Enter. Произвольный
  текст не считается выбранным городом; при отправке без выбора — ошибка у поля.
- «Точное время неизвестно» делает отсутствие времени явным: в запрос уходит
  `birth_time: null`, 12:00 не подставляется. При противоречии между отметкой и
  введённым временем — одно понятное действие для исправления.
- Кнопка «Построить карту и открыть чат» активна после корректной даты и выбранного
  места. На отправке — состояние расчёта и защита от повторного запроса
  (`POST /charts/natal` не идемпотентен). При ошибке значения сохраняются, есть повтор.
- Ошибки валидации от API (`INPUT_REQUIRED` + `issues`) показываются у своих полей.
- Часовой пояс в браузере не угадывается: backend получает `place_id` и дату.
- «Как это работает» раскрывает объяснение: расчёт отдельно от интерпретации;
  без времени часть выводов недоступна.

### Персональные данные

Отдельная раскрываемая панель «Персональные данные»: какие данные вводятся, зачем,
где политика, как запросить удаление или изменение. Точные тексты, сроки хранения,
оператор и адрес политики берутся только из утверждённых материалов; заглушки не
публикуются.

Если нужна галочка согласия, она **снята по умолчанию**, с отдельным понятным
текстом и активным действием пользователя. Заранее отмеченная галочка не
называется согласием. Под ней не прячется аналитика или маркетинг. Юридическая
формулировка и необходимость согласия утверждаются до публикации (ст. 9 152-ФЗ;
для GDPR — разъяснения EDPB о недопустимости заранее отмеченных полей).

Плашки «Ваши данные в безопасности» и «Не передаём третьим лицам» не
показываются, пока это не подтверждено (см. `render_review.md`, Р1).

## 5. «Карта готова» и состояния сессии (Э3–Э6)

При открытии страницы интерфейс вызывает `POST /session/bootstrap` (вариант D,
`decisions.md`, 1.1) и выбирает экран:

| Ответ bootstrap | Экран |
|---|---|
| `empty` | Э1 |
| `chart_ready`, `chart_stale = false` | Э3 (или Э4 при `time_is_unknown`) |
| `chart_ready`, `chart_stale = true` | Э5: карта с пометкой и действием «Пересчитать» |
| `chart_unavailable` | Э6: сохранённые данные и «Построить карту заново» |

Э3 показывает место, локальные дату и время (если известно), фактически применённый
пояс, систему домов и тип зодиака — только из `ChartDTO`. Круг слева (на телефоне —
сверху), «Главные акценты»: Солнце, Луна, ASC только при известном времени. Без
времени (Э4) карточка ASC заменяется пояснением «Нужно время рождения».

Действия: «Посмотреть карту подробно» (M1) и «Открыть персональный чат» с
тематическими кнопками (M2; до M2 не показываются или честно помечены).

Обработка ответов `POST /charts/natal`:

- любой 409 по сессии → bootstrap; введённые значения сохраняются, повтор только
  по нажатию;
- `RESULT_SUPERSEDED` → bootstrap и показ актуальной карты с пояснением «карту
  изменили в другой вкладке»;
- 429 и 503 → сообщение с учётом `Retry-After`, без автоповтора в цикле;
- «Новая карта» определяется по `chart_identity`, а не по `state_version`.

## 6. Подробная карта (Э7)

Переходы: с Э3–Э5 и (в M2) из компактной карты в чате. Заголовок, исходные данные,
пояснение о точности, возврат назад.

Desktop: большой круг и короткое резюме, ниже разделы. Mobile: круг во всю ширину,
затем резюме и раскрывающиеся секции.

Разделы:

- **Планеты и точки:** знак, градусы и минуты, дом только если определён,
  ретроградность при наличии.
- **Дома:** куспиды, только при известном времени.
- **Аспекты:** по умолчанию короткий список точных аспектов (`category == "exact"`,
  `decisions.md`, №2), рядом раскрывающийся «Все аспекты (N)». Сортировка по
  орбису по возрастанию, затем стабильный порядок. Фронтенд не придумывает порог.
  Пустой список точных аспектов — понятное пустое состояние, полный список доступен.
  Фильтры по типу допустимы, если не мешают основному сценарию.
- **Стихии:** числа и полосы с подписанным основанием подсчёта — только при
  утверждённой методике. Пока её нет, блок показывает пустое состояние, а не
  проценты.
- **«Качества»** не показываются без утверждённой методики.

Выбор объекта на круге выделяет строку данных; выбор аспекта — линию и два объекта.
Есть способ снять выделение. Все значения доступны без SVG и без hover.

## 7. Круг натальной карты

Отдельный компонент `NatalChartSvg` (или эквивалент в стеке) с квадратным
`viewBox`. Принимает данные `ChartDTO`, вариант (`full`, `compact`) и состояние
выбора.

Разделение ответственности: движок — долготы, куспиды, аспекты, знаки и допустимость
результата; адаптер фронтенда — перевод долгот в координаты; SVG — геометрия,
символы, подсветка и события. Фронтенд не пересчитывает дома, орбисы, знаки и
часовые пояса и не содержит параллельного расчётного источника.

- Слои: кольца зодиака и домов → куспиды и оси → линии аспектов → планеты и подписи
  → интерактивные цели.
- Ориентация: ASC слева, зодиак против часовой стрелки. Соглашение проверяется
  тестом на известной карте из движка, а не по рендеру. Без времени — ориентация
  по `decisions.md`, №12.
- Аспекты — хорды между позициями планет на внутреннем кольце.
- Близкие планеты разносятся по дуге, к истинной долготе ведут засечка и выносная
  линия; долгота данных не меняется.
- Углы ASC/DSC/MC/IC — только если рассчитаны.
- `full`: градусы, засечки, номера домов. `compact` (боковая панель, телефон):
  только знаки и символы, точные значения — в HTML рядом.
- Состояния `loading`, `ready`, `partial`, `error`. Декоративный круг вместо
  настоящей карты не показывается.
- Для локального просмотра допустимы явно помеченные фикстуры — реальный вывод
  движка; они никогда не показываются как пользовательский расчёт.

## 8. Чат (Э8, Э9) — M2

Композиция Р4: список диалогов, переписка, поле ввода, панель с компактным кругом,
ключевыми положениями и «Открыть карту полностью». На телефоне — один экран:
диалоги открываются шторкой, карта — отдельной панелью.

- Интерпретация опирается на `chart_identity`, отображаемый в UI; подпись карты в
  чате — дата и время рождения, а не номер версии состояния.
- Другая дата или город в сообщении не меняет карту. Ответ строится по текущей
  карте, рядом — явное действие «Изменить данные рождения», ведущее на форму с
  текущими значениями и подтверждением пересчёта.
- Судьба старых сообщений после смены карты решается до M2 (`decisions.md`, №14).

## 9. Мобильная версия

Мобильная версия — не уменьшенный desktop, а те же данные в одну колонку по
важности. Макеты — в `mobile/`.

- Брейкпоинты по содержимому: до ~600 px — одна колонка; 600–1024 — две;
  шире — как на рендерах.
- Круг на телефоне всегда в варианте `compact`.
- Символ планеты на 360 px занимает около 17 px, поэтому нажатие в секторе кольца
  выбирает ближайшую по углу планету. Аспекты выбираются только в списке.
- Выбранная строка ниже круга получает ссылку «Показать на карте».
- На мобильном Э7 разделы представлены раскрывающимися секциями, таблицы аспектов —
  двухстрочными элементами списка. Горизонтального скролла таблиц нет.
- Выпадающий список городов не закрывается экранной клавиатурой: поле при фокусе
  прокручивается вверх.
- Поле ввода чата (M2) закреплено внизу и поднимается над клавиатурой.
- Проверка на реальном телефоне, а не только в эмуляторе: клавиатура, `100vh`,
  поля даты, безопасные зоны.

## 10. Адаптивность, доступность, состояния

- Ширины проверки: ~360, ~768, ~1440 px.
- Видимые подписи полей, ошибки связаны с полями, различимый фокус, область нажатия
  не меньше 44 px. Асинхронный результат и ошибки озвучиваются средствами
  доступности. У SVG есть текстовое название и описание; рядом — те же данные в HTML.
- Состояния: пустая форма, подсказки города, ошибка выбора города, некорректная дата,
  отсутствие времени, ожидание, успешный расчёт, частичный расчёт, устаревшая карта,
  недоступная карта, отказ API или сети, лимит (429), занятость (503), пустые точные
  аспекты, пустой полный список, отсутствие методики стихий.
- После открытия чистой сессии не показываются данные из примеров рендеров.
- Введённые персональные данные не попадают в клиентскую телеметрию без утверждённой
  политики.

## 11. Границы первой реализации

Входит: Э1–Э7, круг `full` и `compact`, выделение круг ↔ список, мобильные состояния.

Не входит: чат и интерпретация (M2), «Поделиться», «Скачать», «Печать», навигация
по транзитам, соляру, лунару и совместимости, страница справочника символов,
транзитное кольцо, редактирование карты из текста чата, любые астрологические
вычисления во фронтенде. Кнопки без реального действия убираются из готовых экранов.

## 12. Этапы

1. Разведка и решения, без кода: стек, фактические ответы API, закрытие решений
   1, 2, 5, 7, 8 из `decisions.md`.
2. Токены и SVG-символы.
3. `NatalChartSvg` на фикстуре: тест ориентации, `full`, `compact`, без времени.
4. Форма ввода: поля, `GET /places`, флаг неизвестного времени, ошибки из `issues`.
5. Вертикаль M1: bootstrap, `POST /charts/natal`, Э3–Э6, обработка 409, 429, 503.
6. Подробная карта Э7.
7. Доводка: выделение, три ширины, доступность, скриншоты для приёмки.

## 13. Приёмка

1. При дате и выбранном месте без времени получается космограмма: доступные
   позиции есть, ASC и дома не выдаются как рассчитанные.
2. Подсказки места выбираются мышью и клавиатурой; одноимённые места различимы;
   неверная дата и невыбранное место не отправляются и объясняются у поля.
3. Э3, Э7 и (в M2) панель чата показывают одну карту (`chart_identity`) и одинаковые
   значения. Обновление страницы, истёкшая сессия, `chart_stale` и
   `chart_unavailable` обрабатываются по разделу 5, без выдуманной карты.
4. На Э7 видны точные аспекты и раскрывается полный список; число и порядок
   совпадают с ответом движка. Пустые списки не ломают страницу.
5. Блок стихий без утверждённой методики не показывает чисел.
6. Круг читается в `full` и `compact`, не выходит за экран на 360 px, метки близких
   планет не сливаются; выделение на круге согласовано со списком.
7. Проверены клавиатура, фокус, загрузка и ошибки, масштабирование текста, доступ к
   данным без взаимодействия с рисунком.
8. Предоставлены скриншоты каждого экрана на desktop и ключевых состояний на mobile,
   сравнение с рендерами и мобильными макетами и перечень осознанных отличий.

## 14. Формат ответа кодинг-агента

Сначала обзор найденного проекта и таблица решений, затем план небольшими этапами,
затем реализация с перечнем изменённых файлов, скриншотами и результатами приёмки.
Всё, что ждёт решения, обозначается явно и не маскируется цифрами из рендеров.
