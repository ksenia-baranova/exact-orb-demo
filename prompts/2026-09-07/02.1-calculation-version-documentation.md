## Контракт, который обязана отражать документация

### 1. Форма API и чистота

В модуле **нет** вычисляемой при импорте глобальной константы
`CALCULATION_VERSION`.

Реализованы четыре элемента:

```python
compute_calculation_version_record(
    *,
    ephemeris_path: str | os.PathLike[str],
    selena_method: str,
    body_ids: Mapping[str, int],
    ephemeris_flags: int,
) -> CalculationVersionRecord

calculation_version_of(record: CalculationVersionRecord) -> str

compute_calculation_version(
    *,
    ephemeris_path: str | os.PathLike[str],
    selena_method: str,
    body_ids: Mapping[str, int],
    ephemeris_flags: int,
) -> str

log_calculation_version(record: CalculationVersionRecord) -> None
```

- `CalculationVersionRecord` — frozen strict-модель ровно из девяти
  компонент.
- `compute_calculation_version_record()` — effectful-сборщик: читает
  файловую систему и metadata окружения, но не логирует.
- `calculation_version_of()` — чистое каноническое хэширование готовой
  записи.
- `compute_calculation_version()` — удобная композиция сборщика и хэширования;
  она также не логирует, но не является чистой в математическом смысле,
  поскольку читает окружение через сборщик.
- `log_calculation_version()` — отдельный startup-эффект.

Термин `CalculationVersion` можно сохранять как имя концепции или значения,
передаваемого в `calculation_key`. Но запись `CALCULATION_VERSION` не должна
выглядеть как существующий module-level symbol. В псевдокоде использовать
локальное `calculation_version` или `version` и пояснить, что значение один
раз создаётся точкой композиции и передаётся в `ChartArtifactResolver`.

### 2. Startup-композиция и текущий статус wiring

Будущая точка композиции обязана выполнять операции в таком порядке:

```python
status = configure_ephemeris(...)
record = compute_calculation_version_record(
    ephemeris_path=status.path,
    selena_method=get_selena_method_name(),
    body_ids=DEFAULT_BODY_IDS,
    ephemeris_flags=DEFAULT_EPHEMERIS_FLAGS,
)
calculation_version = calculation_version_of(record)
log_calculation_version(record)
artifacts = ChartArtifactResolver(..., version=calculation_version)
```

Значения 6–9 передаются явно из уже замороженной startup-конфигурации и
именованных дефолтов. Сборщик не должен повторно выбирать конфигурацию из
environment.

При этом `bootstrap.py` пока не существует, а production-код и CLI пока не
вызывают функции `calculation.version`. Документация должна различать:

- **реализованный механизм A2** — record, fingerprint, ошибки, логирование,
  тесты и интеграционная инвалидация кэша;
- **ещё не выполненное wiring C3** — единичный startup-вызов и передача
  результата в реальный `ChartArtifactResolver`.

Не писать, что текущее приложение уже отказывается стартовать из-за ошибки
`CalculationVersion`, и не добавлять вызов в CLI в рамках документационной
задачи.

### 3. Девять компонент

Документы должны одинаково перечислять:

1. `ENGINE_VERSION` — явная строковая константа; выбран вариант с ручным
   повышением при изменении алгоритма или численно значимого дефолта, а не
   хэш исходников;
2. sha256 канонического содержимого `AspectConfig.natal()`,
   `AspectConfig.transit()`, `ConfigurationConfig()` и `StrengthConfig()`;
3. непустой `swisseph.version`; отсутствие/пустое значение —
   `EphemerisConfigurationError`;
4. имя и версия Python-дистрибутива, предоставляющего `swisseph`;
5. sha256 нативного `.pyd`/`.so`, если доступен;
6. упорядоченный набор `(basename, sha256)` всех непосредственных файлов
   `*.se1` каталога эфемерид;
7. `selena_method` из замороженной конфигурации;
8. sha256 отсортированных пар `body name -> swe_id` из
   `DEFAULT_BODY_IDS`;
9. `DEFAULT_EPHEMERIS_FLAGS`, то есть значение, передаваемое техникой в
   `calculate_natal()` **до** внутреннего добавления `swe.FLG_SPEED`.

Для компоненты 9 явно назвать `DEFAULT_EPHEMERIS_FLAGS` единым источником и
для сигнатуры `calculate_natal()`, и для будущей композиции. Не предлагать
читать флаги из готовой `NatalChart`: там хранится post-OR значение.

### 4. Детерминизм и точная файловая семантика

- Формат: канонический JSON UTF-8 с `sort_keys=True`, без пробелов,
  `ensure_ascii=False`; sha256; префикс `eo:calcver:v1:`.
- В payload входит `schema_version = "v1"` и ровно девять полей записи.
- `ephemeris_path` в payload не входит.
- Учитываются только непосредственные обычные файлы каталога, без
  рекурсивного обхода.
- Суффикс `.se1` сопоставляется **без учёта регистра**. Это существенно на
  Windows: `SEMO_18.SE1` должен участвовать в отпечатке так же, как
  `semo_18.se1`.
- Файлы сортируются по `(name.casefold(), name)`; в payload входят basename и
  digest содержимого.
- Два разных пути с теми же именами и байтами дают один отпечаток.
- Один и тот же вход, в том числе между процессами с разным hash seed, даёт
  один отпечаток.
- `CALCULATION_VERSION_SCHEMA` и стабильный marker
  `UNRESOLVED_DISTRIBUTION = "<unresolved>"` являются частью контракта ключа;
  изменение любого из них инвалидирует кэш.
- `tzdata` не входит: её эффект уже отражается в `utc_datetime` входа ключа.

### 5. Биндинг Swiss Ephemeris

Используется `importlib.metadata.packages_distributions()`:

- одинаковые имена дистрибутива дедуплицируются без учёта регистра;
- ровно один provider → в запись входит `name==version`;
- ни одного provider → стабильный marker `<unresolved>`, старт не блокируется
  только по этой причине;
- больше одного различимого provider →
  `EphemerisBindingAmbiguousError`, fail-fast;
- ошибка чтения mapping или версии единственного provider →
  `EphemerisConfigurationError`.

Исправить старую формулировку «невозможно сопоставить **или** найдено
несколько — приложение не стартует»: отсутствие mapping реализовано как
осознанный стабильный marker, а неоднозначность — как ошибка.

### 6. Нативный модуль и ослабленный отпечаток

`.pyd` и `.so` распознаются без учёта регистра. Если origin отсутствует,
указывает не на поддерживаемый обычный файл или файл нельзя прочитать,
`native_module_digest = None`.

Это не ошибка сборки record. `log_calculation_version()` пишет отдельный
WARNING `calculation_version_weakened` с причиной
`native_module_digest_unavailable`. Обычный record/version log содержит все
компоненты, но не абсолютные пути.

### 7. Каталог эфемерид и fallback

Не смешивать два слоя:

- `configure_ephemeris()` и расчётное ядро по Т-ЭФ-5 допускают fallback;
- сборщик `CalculationVersion` требует, чтобы переданный путь существовал и
  был каталогом, иначе поднимает `EphemerisConfigurationError`;
- существующий пустой или частично заполненный каталог корректен для
  отпечатка: пустой/частичный список файлов стабильно хэшируется, а ядро может
  работать в fallback;
- cache-enabled bootstrap после C3 должен будет отказать только при
  отсутствующем/не-каталоге, потому что не может построить воспроизводимую
  версию окружения;
- текущий CLI ещё не соединён с `CalculationVersion`, поэтому его фактическое
  fallback-поведение не объявлять изменённым.

README и Т-ЭФ-5 должны формулировать это без логического конфликта: fallback
как режим Swiss Ephemeris сохраняется, а версия расчёта задаёт более сильное
предусловие будущего cache-enabled startup.

При этом нельзя повторять действующую фразу README «расчёт не падает». Она
неверна уже независимо от `CalculationVersion`: `_add_derived_points()`
вызывается безусловно, поэтому Селена считается для любой натальной карты и
любой космограммы независимо от `include`; `selena.py` превращает
предупреждение Moshier в `RuntimeError`. Это известный открытый Т-ЭФ-24.
Документация должна честно разделить:

- Swiss Ephemeris переходит в fallback для доступных ему тел;
- любой natal/cosmogram сейчас падает в fallback при расчёте Селены —
  Т-ЭФ-24; сужение `include` этот отказ не обходит;
- отсутствие каталога станет отдельным startup-failure version collector
  только после wiring C3.

Не объявлять Т-ЭФ-24 решённым и не менять код Селены в этой задаче.

## Согласованность формулировок

После правок во всех актуальных документах должны одновременно выполняться
утверждения:

- путь не входит в отпечаток, содержимое файлов входит;
- `.se1` сопоставляется без учёта регистра;
- отсутствующий каталог — typed error сборщика, существующий пустой каталог —
  валидный record;
- zero provider — `<unresolved>`, multiple providers — fail-fast;
- отсутствие native digest ослабляет отпечаток и логируется, но не блокирует
  сборку;
- pure boundary — `calculation_version_of(record)`, а filesystem collector
  effectful;
- значение не вычисляется при импорте;
- `ENGINE_VERSION` — ручная константа;
- флаги берутся из `DEFAULT_EPHEMERIS_FLAGS` до внутреннего `FLG_SPEED`;
- A2 реализована и протестирована, C3 wiring ещё впереди.

## Проверки

Обязательно:

```powershell
git diff --check
rg -n -i 'compute_calculation_version\(ephemeris_path: str\)|файла `calculation/version.py` нет|6 компонент|ENGINE_VERSION.*константа или|покрывается тестами в A2|до реализации `calculation/version.py`' README.md docs
rg -n 'CALCULATION_VERSION' README.md docs/requirements docs/architecture docs/sequence_diagrams/build_natal docs/sequence_diagrams/chart_artifacts
```

Одинарные кавычки обязательны для PowerShell: иначе бэктики внутри паттерна
будут восприняты как escape-символы. `-i` нужен, чтобы команда находила как
`Файла`, так и `файла`. Первую команду полезно выполнить до правок как
контроль того, что проверка действительно видит известные устаревшие строки,
а после правок она не должна находить ни одной из них.

Второй `rg` не обязан вернуть пустой результат: концептуальные упоминания
могут быть корректны. Кроме того, паттерн намеренно находит
`CALCULATION_VERSION_SCHEMA` — это реально существующая module-level константа
схемы и часть контракта ключа, её исправлять или переименовывать не нужно.
Для остальных совпадений убедиться, что они не утверждают наличие глобального
вычисленного значения `CALCULATION_VERSION` и не описывают A2 как будущую
работу.

Если в окружении уже доступен используемый проектом PlantUML, проверить
изменённые `.puml`. Не скачивать инструменты и не вводить новый quality gate.

Для docs-only изменения полный `pytest` повторно запускать не требуется.
Указать в отчёте baseline реализации:

```text
pytest -p no:cacheprovider tests/test_calculation_version.py -q
42 passed

pytest -p no:cacheprovider -q
1360 passed in 36.02s
```

Не выдавать эти результаты за тесты, запущенные в документационной ветке:
это фактические проверки коммита `55f0f03`.

## Критерии приёмки

- Актуальные требования, ADR, roadmap, overview, архитектурный долг и sequence
  diagrams не противоречат реализации `CalculationVersion`.
- Документы описывают точный API, девять компонент и error/fallback-семантику.
- Нигде не заявлено, что существует глобальная импортная
  `CALCULATION_VERSION`.
- Статус завершённой A2, реализованного механизма B-7 и будущего вступления
  системного инварианта B-7 в силу после C3 разведены явно.
- Исторические промты и legacy `build_charts` не переписаны.
- Код, тесты, зависимости и публичные runtime-контракты не изменены.
- Итоговый отчёт перечисляет изменённые документы, снятые противоречия,
  реально выполненные проверки и оставшееся ограничение: production startup
  wiring появится только вместе с точкой композиции.
