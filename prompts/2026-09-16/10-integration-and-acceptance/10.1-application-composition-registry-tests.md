# Промт 10.1 — Полнота реестра команд при сборке application

**Статус:** подготовлен 2026-09-19 перед исполнением.
**Зависимости:** реализован полный однопроходный и retry-flow
`ApplicationOrchestrator` до 9.R1 включительно.
**Основание:** FR-04/05 и AC-3/4
[требований ApplicationOrchestrator](../../../docs/requirements/component_responsibilities/exact-orb_application_orchestrator_requirements.md),
[ADR-0006](../../../docs/requirements/decisions/0006-application-orchestrator.md) и
[карточка 10.1 плана](../../../docs/project_management/application_orchestrator_implementation_plan.md).

## Что делаем и зачем

Координатор уже умеет безопасно отказать, если получил команду без Handler.
Для production-сборки этого недостаточно: известная поддерживаемая команда не
должна впервые обнаруживать ошибку конфигурации в пользовательском запросе.
Такой пропуск нужно находить при запуске приложения, до начала `execute()`.

Зафиксируем минимальный реестр текущего продукта: `BuildNatalCommand` обязан
иметь собственный Handler. Регистрация базового `Command` не заменяет точное
назначение, потому что routing намеренно использует `type(command)` без MRO,
`isinstance` и fallback. Положительный тест полного mapping нужен, чтобы
проверка не превратилась в безусловный запрет запуска.

**Результат для менеджеров:** приложение не начнёт обслуживать запросы в
заведомо неполной конфигурации. Ошибка подключения Build Natal будет видна на
старте, а не после обращения пользователя; корректная конфигурация продолжит
собираться из явно переданных зависимостей.

## Целевой контракт для 10.2

Новый тест фиксирует одну публичную точку сборки:

```python
build_application_orchestrator(
    *,
    context: ContextService,
    clock: Callable[[], datetime],
    resolver: BirthDataResolverPort,
    artifacts: ChartArtifactPort,
) -> ApplicationOrchestrator
```

`composition.py` должен локально хранить неизменяемый набор поддерживаемых
типов команд и локальную функцию проверки registry. На этом этапе набор равен
`frozenset({BuildNatalCommand})`. Публичная функция 10.2 создаст реальный
`BuildNatalHandler` из переданных `resolver` и `artifacts`, сформирует точный
mapping, проверит полноту и только затем вернёт `ApplicationOrchestrator` с
переданными `context` и `clock`.

Проверка registry должна принимать полный mapping и выбрасывать `ValueError`,
в котором назван `BuildNatalCommand`, если точной регистрации нет. Mapping с
одним базовым `Command` остаётся неполным. Тест публичной сборки временно
расширяет локальный supported-set тестовой командой и доказывает, что функция
завершается ошибкой до возврата координатора; `execute()` не вызывается.

Разрешено проверять приватные поля собранных объектов только как свидетельство
startup-инварианта: переданные зависимости сохранены по identity, а registry
содержит реальный `BuildNatalHandler` ровно для `BuildNatalCommand`. Не вводи
публичный API регистрации или замены Handler ради теста.

## Исполнение и проверки

Создай четыре детерминированных теста:

1. Полный `{BuildNatalCommand: handler}` проходит локальную проверку.
2. Пустой mapping отвергается с указанием недостающей команды.
3. `{Command: handler}` не считается fallback для `BuildNatalCommand`.
4. Публичная сборка с явными зависимостями создаёт реальный Handler и всегда
   запускает проверку полноты до возврата координатора.

Не используй skip, xfail, `importorskip` или временный production stub.
Поскольку `composition.py` появится в 10.2, ожидаемый результат 10.1 — ошибка
сборки `ModuleNotFoundError: exact_orb.application.composition`. Дополнительно
проверь синтаксис нового теста через `ast.parse`. При ожидаемом red связанные
R и полный F не запускай: они не могут дать новое свидетельство до 10.2.

```powershell
.\.venv\Scripts\python.exe -B -m pytest -p no:cacheprovider tests/application/test_application_composition.py -q
.\.venv\Scripts\python.exe -B -c "import ast,pathlib; p=pathlib.Path('tests/application/test_application_composition.py'); ast.parse(p.read_text(encoding='utf-8'), filename=str(p)); print('AST OK')"
```

Запиши фактическое число collected/errors, exit code и границу доказанного в
§1.3 плана и README. Проверь `git diff --check`, локальные Markdown-ссылки,
парность code fences и пустой staged index. FR-05 станет исполняемым только
после 10.2; реальные application/session/Handler пути остаются 10.3–10.5.
