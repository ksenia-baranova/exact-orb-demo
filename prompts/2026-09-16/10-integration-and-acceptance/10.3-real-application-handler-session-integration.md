## Что делаем и зачем

Отдельные части пользовательской операции уже проверены: Handler строит карту,
Orchestrator управляет стадиями и сохранением, `ContextService` классифицирует
ответы persistence, а composition связывает команду с Handler. Теперь нужно
доказать, что эти части работают вместе без тестовой подмены центральных
компонентов.

Создай интеграционный стенд с реальными `ApplicationOrchestrator`,
`BuildNatalHandler`, `ContextService`, `InMemorySessionPersistence`,
`BirthDataResolver`, `ChartArtifactResolver`, calculation engine и cache.
Тестовая граница отвечает только за входную команду, часы, создание сессии и
наблюдение результата. Для технического сценария исчезновения сессии допустим
листовой artifact seam: он обязан сначала делегировать настоящий расчёт и лишь
затем удалить сессию перед commit.

**Результат для менеджеров:** мы подтверждаем не отдельные классы, а цельную
операцию. Валидные данные создают natal-карту или cosmogram, результат
сохраняется с новой версией, повторный одинаковый расчёт использует cache,
пользовательские и технические отказы не меняют state, а потеря сессии между
расчётом и сохранением получает отдельный безопасный ответ.

## Границы работы

Разрешено менять только:

- `tests/fixtures/application.py` — общий реальный тестовый стенд;
- `tests/application/test_orchestrator_integration.py` — новые сквозные проверки;
- `tests/application/test_build_natal_integration.py` — только перенести `_stand`
  в общую fixture и заменить его вызовы без изменения существующих assertions;
- §1.3 плана и README серии — фактический статус и результаты;
- этот промт.

Не меняй production-код, engine, golden-данные, допуски, requirements, ADR,
диаграммы и прежние промты. Не мокай Orchestrator, ContextService, Handler или
InMemory persistence. Не добавляй сеть, transport, cookie/session bootstrap,
DI-framework, singleton, admission controller или новые зависимости. Не
превращай integration-тест в проверку приватных внутренних полей. Коммит, push
и PR требуют отдельного указания; несвязанные файлы рабочего дерева сохраняй.

## Общий стенд

Перенеси существующую сборку `_stand` из
`test_build_natal_integration.py` в `tests/fixtures/application.py`. Сохрани
те же реальные catalog, resolver, cache, executor, engine, artifact resolver и
Handler. Дополнительно создай один InMemory aggregate, `ContextService` и
Orchestrator через `build_application_orchestrator` из 10.2. Одни и те же
resolver/artifact dependencies должны использоваться Handler- и
application-путями, чтобы счётчики cache наблюдали реальную общую работу.

Стенд должен быть context manager и владеть временем жизни executor. Экспортируй
сам dataclass и функцию сборки. Существующие четыре Handler-интеграционных теста
переведи на общий стенд; их assertions не меняй.

## Интеграционные сценарии

В новом `test_orchestrator_integration.py` проверь:

1. **Natal, cache miss и cache hit.** Создай две реальные сессии и выполни одну
   команду с разными `RunContext`. Обе операции возвращают
   `ApplicationCommitted` версии 1, сохраняют birth data и `base_chart`, имеют
   исходные `run_id`; первый вызов даёт miss/put, второй — hit того же artifact.
2. **Cosmogram.** Отсутствующее время рождения приводит к committed cosmogram;
   в state сохраняется исходный `birth_time=None`, а spec и artifact согласованы.
3. **Штатные non-success.** Неизвестное место даёт структурированный
   `ApplicationInputRequired`, сломанная timezone —
   `ApplicationResolutionFailure`, полярный расчёт —
   `ApplicationCalculationFailure(HOUSES_DEGENERATE)`. Во всех случаях версия
   реальной сессии остаётся 0 и расчётный state не заполняется.
4. **Сессия отсутствует до Handler.** Операция возвращает load-stage
   `ApplicationSessionAbsent`; calculation/cache не запускаются.
5. **Сессия исчезает после Handler.** Листовой seam делегирует настоящий
   artifact resolver, удаляет сессию и возвращает рассчитанный artifact.
   Commit получает `SessionAbsent`, наружу выходит
   `SESSION_LOST_DURING_OPERATION` с `handler_status=SUCCESS`, без публикации
   версии результата.

Для отрицательных сценариев обязательно сохраняй положительные контроли natal
и cosmogram в том же файле. Не используй `sleep`, случайные задержки или
реальное ожидание как доказательство порядка.

```powershell
.\.venv\Scripts\python.exe -B -m pytest -p no:cacheprovider -q
```

Дополнительно проверь AST трёх тестовых файлов, локальные Markdown-ссылки,
code fences, `git diff --check`, точный состав изменений и пустой staged index.
Запиши реальные команды и результаты в §1.3 плана и README. Не объявляй
закрытыми lost-CAS 10.4, SQLite concurrency 10.5, нагрузочные профили 10.6/10.7
или полную приёмку R3.2.
