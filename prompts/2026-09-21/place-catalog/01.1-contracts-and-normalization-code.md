# Промт 1.1 — контракты поиска мест и каноническая нормализация

## Что делаем и зачем

Добавить лёгкий публичный контракт поиска подсказок и одну чистую функцию
нормализации в `exact_orb.birth.places`. В следующих карточках builder и
SQLite-adapter будут импортировать эту же функцию, чтобы ключи индекса и
поисковые запросы обрабатывались одинаково.

Единственный production-результат — search-типы и normalizer. Существующие
`PlaceCatalog.lookup`, `ResolvedPlace`, `PlaceNotFound` и JSONL-adapter
сохраняют поведение. Поиск по базе в этой карточке не реализуется.

## Реализация

### 1. Общие типы

В `src/exact_orb/birth/places.py` добавить:

```python
ALLOWED_ALTERNATE_LANGUAGES = frozenset({"ru"})

PlaceQueryErrorCode = Literal[
    "EMPTY",
    "TOO_LONG",
    "CONTROL_CHARACTERS",
    "NO_SEARCHABLE_CHARACTERS",
]


class PlaceSuggestion(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")

    place_id: str
    display_name: str
    admin1_name: str | None
    country_code: str


class PlaceSuggestions(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")

    items: tuple[PlaceSuggestion, ...]


class InvalidPlaceQuery(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")

    code: PlaceQueryErrorCode


PlaceSearchOutcome = PlaceSuggestions | InvalidPlaceQuery


class PlaceSearch(Protocol):
    async def search(
        self,
        query: str,
        *,
        limit: int = 10,
    ) -> PlaceSearchOutcome: ...
```

Не добавлять координаты, timezone, новые defaults или дополнительные поля
подсказки. `PlaceSuggestions(items=())` — самостоятельный успешный исход.
Проверка strict limit `1..20` принадлежит будущему adapter в карточке 4.1;
здесь фиксируется только сигнатура порта.

### 2. Единственная функция нормализации

Добавить `normalize_place_query(query: str) -> str | InvalidPlaceQuery`.
Функция не выполняет I/O и не зависит от builder, adapter или HTTP.

Порядок обработки обязателен:

1. Проверить исходную строку на Unicode control characters — категорию `Cc`
   через `unicodedata.category`. При наличии вернуть
   `InvalidPlaceQuery(code="CONTROL_CHARACTERS")` до любых преобразований.
   Поэтому tab, newline и другие управляющие whitespace не исчезают при
   схлопывании пробелов, а отклоняются.
2. Применить Unicode NFKC.
3. Удалить крайние Unicode whitespace и схлопнуть внутренние последовательности
   в один ASCII-пробел (`" ".join(value.split())`).
4. Применить `casefold()`.
5. Заменить `ё` на `е`.
6. Проверить полученный ключ в порядке: пустой → `EMPTY`; больше 200 Unicode
   code points → `TOO_LONG`; нет ни одного `str.isalnum()` символа →
   `NO_SEARCHABLE_CHARACTERS`. Иначе вернуть ключ.

Длину измерять после всех преобразований; не ограничивать алфавит кириллицей
и латиницей, не удалять пунктуацию и не добавлять accent folding или
транслитерацию. Значения кроме `str` находятся вне Python-контракта функции;
не преобразовывать их в строки и не вводить новый query error code.

### 3. Экспорты

Обновить `places.__all__` для новых контрактов, константы и normalizer.
Из `exact_orb.birth` реэкспортировать только четыре новых имени:
`PlaceSearch`, `PlaceSuggestion`, `PlaceSuggestions`, `InvalidPlaceQuery`.
Остальные существующие экспорты сохранить. Импорт пакета не должен загружать
`sqlite3`.

## Приёмка и проверки

- Новые модели immutable и `extra="forbid"`, поля совпадают с §3 требований.
- Чистая функция соблюдает установленный порядок нормализации и исходов.
- Пустая успешная выдача отличается от invalid query.
- Существующие lookup и JSONL-поведение не изменены.
- Четыре публичных импорта доступны без загрузки `sqlite3`.
