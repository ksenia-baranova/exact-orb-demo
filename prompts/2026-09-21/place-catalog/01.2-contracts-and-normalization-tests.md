# Промт 1.2 — тесты контрактов поиска мест и нормализации

## Что делаем и зачем

Добавить отдельные тесты уже реализованной карточки 1.1. Тесты должны закрепить
единую Unicode-нормализацию для будущих builder и runtime search, отличить
невалидный запрос от успешной пустой выдачи и подтвердить неизменяемость
публичных search-моделей.

Production-код в этой карточке не меняется. Если тест обнаруживает расхождение
реализации с действующим контрактом, зафиксировать точный сценарий и вернуть
исправление в карточку 1.1 либо отдельную correction-карточку.

## Реализация тестов

Создать `tests/test_place_search_contracts.py` и проверить наблюдаемый контракт,
не внутренние детали функции.

### 1. Каноническая нормализация

Закрепить:

- Unicode NFKC на compatibility-символах;
- trim и схлопывание Unicode whitespace до одного ASCII-пробела;
- Unicode `casefold()`, включая преобразование, отличное от простого `lower()`;
- замену `Ё/ё` на `е` после casefold;
- сохранение допустимых Unicode-букв, диакритики, дефиса и других письменностей
  без accent folding и транслитерации;
- принятие ровно 200 code points готового ключа;
- измерение длины после NFKC на символе, который раскрывается в несколько code
  points.

Тестами на перекрывающихся условиях доказать порядок валидации:

1. raw `Cc` проверяется до whitespace folding: tab/newline/NUL возвращают
   `CONTROL_CHARACTERS`;
2. строка из более чем 200 Unicode whitespace после нормализации возвращает
   `EMPTY`, а не `TOO_LONG`;
3. 201 непоисковый символ возвращает `TOO_LONG`, а не
   `NO_SEARCHABLE_CHARACTERS`;
4. короткая пунктуация без букв и цифр возвращает
   `NO_SEARCHABLE_CHARACTERS`.

Значения кроме `str` находятся вне контракта и в этой карточке не тестируются.

### 2. Search-модели и исходы

Проверить точный состав публичных полей:

- `PlaceSuggestion`: `place_id`, `display_name`, `admin1_name`, `country_code`;
- `PlaceSuggestions`: `items` как tuple;
- `InvalidPlaceQuery`: `code` из четырёх разрешённых literal-значений.

Для каждой модели доказать `frozen=True` заменой существующего поля и
`extra="forbid"` передачей лишнего поля. Проверять стабильные Pydantic error
types `frozen_instance`, `extra_forbidden` и `literal_error`, а не полный текст
сообщения.

Отдельно подтвердить, что `PlaceSuggestions(items=())` является успешным
исходом и не равен `InvalidPlaceQuery`. Закрепить singleton allow-list как
`frozenset({"ru"})`.

### 3. Публичный API

Импортировать `PlaceSearch`, `PlaceSuggestion`, `PlaceSuggestions` и
`InvalidPlaceQuery` из `exact_orb.birth` и подтвердить identity с объектами из
`exact_orb.birth.places`. Не требовать реэкспорта внутренних aliases,
константы или normalizer из package root.

Проверить локальные Markdown-ссылки нового промта. В журнале плана и итоговом
отчёте записать фактические команды и результаты, затронутые файлы, отклонения
