# Промт 3.1 — SQLite lifecycle и lookup adapter

## Что делаем и зачем

Добавить leaf-adapter `SqlitePlaceCatalog`, который открывает готовый
`places.sqlite` только для чтения, до возврата из `open()` проверяет его как
пригодный runtime-артефакт, разрешает недоверенный `place_id` через существующий
`PlaceCatalog.lookup()` и корректно закрывает одно SQLite-соединение.

Adapter не реализует поиск карточки 4.1 и не участвует в application
composition. Его задача — зафиксировать lifecycle, thread ownership, startup
validation и lookup поверх schema v1 builder карточек 2.1–2.2.

## Публичный lifecycle

Реализовать:

```python
class SqlitePlaceCatalog:
    @classmethod
    async def open(
        cls,
        db_path: str | Path,
        /,
        *,
        executor: ThreadPoolExecutor,
    ) -> Self: ...

    async def lookup(self, place_id: str) -> PlaceResolution: ...

    async def aclose(self) -> None: ...
```

Прямой constructor может создать только unopened lifecycle-state с явно
переданным executor; рабочий экземпляр получают через `open()`. Это позволяет
типизированно отклонять операции до успешного открытия без создания скрытого
соединения.

Executor обязан быть внешним `ThreadPoolExecutor(max_workers=1)`. Adapter не
создаёт и не завершает его. Неверный тип executor или количество workers
отклонять до I/O. Одно соединение создаётся на worker с обычным
`check_same_thread=True`; open/validation, lookup и close исполняются через
`loop.run_in_executor` на этом же executor. Не использовать глобальный pool,
`asyncio.to_thread`, locks вместо thread ownership или
`check_same_thread=False`.

`aclose()` идемпотентен. Одновременные/повторные вызовы должны ожидать один и
тот же close future; новый SQL после начала close запрещён. Adapter сохраняет
executor доступным владельцу и не вызывает `shutdown()`.

`CancelledError` не преобразовывать. Если отменённое ожидание `open()` уже
запустило worker-operation, дождаться его результата и закрыть потенциально
созданное соединение на том же worker перед повторным выбросом cancellation.
Если отменён `aclose()`, завершить уже начатый close и затем распространить
cancellation, чтобы не оставить thread-bound connection владельцу executor.

## Read-only open

Принимать только `str | Path` к file-backed базе. Пустая строка, `:memory:` и
сырой `file:` URI не являются допустимым путём. На worker:

1. выполнить `Path.resolve(strict=True)` и подтвердить обычный файл;
2. получить URI только через `resolved_path.as_uri()`;
3. добавить единственный query parameter `mode=ro`;
4. вызвать `sqlite3.connect(..., uri=True, check_same_thread=True)`.

Не склеивать собственный `file:` URI, не использовать `immutable=1`, не
создавать отсутствующий файл и не открывать write connection. Ошибки пути,
SQLite или startup validation закрывают частично открытое соединение на worker
и становятся `PlaceCatalogUnavailableError` с сохранённой причиной.

## Startup validation schema v1

До успешного возврата `open()` проверить:

- `PRAGMA user_version == 1`;
- наличие таблиц `places`, `place_names`, `catalog_metadata` и точный порядок
  обязательных колонок builder schema v1;
- наличие `idx_place_names_search_key` и `idx_place_names_place_id`;
- ключевые поля search-index: `(search_key COLLATE BINARY, place_id)`;
- ровно одну metadata-строку с `schema_version == 1`;
- parseable JSON `source_checksums` и `build_parameters` с точным обязательным
  shape schema v1;
- три lowercase SHA-256, singleton language allow-list `ru`, feature/country/
  population parameters и непустой `tzdata_version`.

Версию runtime distribution получать через
`importlib.metadata.version("tzdata")`. Если она отличается от catalog
metadata, один раз на `open()` писать WARNING с точным message
`place_catalog_tzdata_version_mismatch` и полями
`catalog_tzdata_version`/`runtime_tzdata_version`, затем продолжать validation.

Одним `SELECT DISTINCT tz_id ... ORDER BY tz_id` получить все зоны каталога и
проверить каждую эффективным runtime `ZoneInfo`. Пустой, нестроковый или
неразрешимый ключ останавливает startup через `PlaceCatalogUnavailableError`.
Пользовательские данные в warning не писать.

## Lookup

До SQL подтвердить, что lifecycle открыт. Типы кроме `str` отклонять
`TypeError` как нарушение Python-контракта. Пустая строка, строка длиннее 32
code points, non-ASCII или содержащая не только ASCII digits возвращает новый
`PlaceNotFound(place_id=...)` без worker/SQL.

Для допустимого ID выполнить на worker один параметризованный exact query по
`places.place_id`:

- неизвестный ID → новый `PlaceNotFound`;
- найденный ID → новый `ResolvedPlace`;
- `canonical_name = display_name`;
- `latitude = latitude_e2 / 100`, `longitude = longitude_e2 / 100`;
- `tz_id` берётся из той же строки.

Каждый вызов возвращает fresh model; не кэшировать и не разделять mutable
экземпляры. Любая техническая ошибка worker/SQLite/model construction после
startup становится `PlaceCatalogUnavailableError`; cancellation проходит
наружу без преобразования.


До тестов вручную собрать synthetic SQLite в ignored `logs/`, открыть adapter с
реальным `ThreadPoolExecutor(max_workers=1)`, проверить Moscow/unknown/invalid
lookup, fresh results, двойной close и typed lookup после close. Отдельными
процессами подтвердить, что `import exact_orb.birth` и
`import exact_orb.birth.adapters` не загружают `sqlite3`, а прямой импорт
`exact_orb.birth.adapters.sqlite` загружает.

Ручными копиями synthetic-базы проверить хотя бы один schema drift и один
неразрешимый timezone: оба open обязаны завершиться
`PlaceCatalogUnavailableError`, не оставляя соединения.

AC-B1–B5 и AC-B7. Полное исполняемое доказательство принадлежит 3.2; search и
lifecycle-часть поискового порта остаются 4.1–4.2.
