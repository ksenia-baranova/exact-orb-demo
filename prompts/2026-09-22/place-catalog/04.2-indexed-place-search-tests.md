## Единственный результат

Создать `tests/test_place_catalog_search.py` с тестами публичной search-
семантики. Использовать настоящий builder для базового временного schema v1

write connection до открытия adapter. Не копировать schema SQL или алгоритм
production search в тесты.

## Базовый поиск и модели

Проверить на synthetic catalog:

- `Москва`, `москва`, `МОСКВА` и `Moscow` возвращают `524901`;
- prefix `Моск` возвращает этот ID один раз, несмотря на несколько aliases;
- `Санкт` и historical alias `Ленинград` возвращают `498817`;
- suggestion всегда использует canonical `display_name`, `admin1_name` и
  country code из `places`, а не matched alias;
- модель не содержит координат, timezone, population или matched name;
- каждый ID из выдачи успешно разрешается прежним `lookup()` того же
  экземпляра;
- повторные и конкурентные search/lookup возвращают равные по значению, но
  отдельные immutable result-модели.

## Ranking, same-name и limit

На управляемых строках schema v1 доказать полный порядок:

1. exact match выше любого prefix независимо от population;
2. current preferred prefix выше current non-preferred;
3. current выше historical;
4. внутри одного rank population сортируется по убыванию;
5. равные rank/population стабильно сортируются по `place_id`.

Отдельно создать два одноимённых места с разными `admin1_name` и
`country_code`: обе подсказки должны остаться различимыми.

Для dedup-before-limit дать одному месту несколько совпавших aliases перед
другими местами и запросить малый limit. Результат обязан содержать ровно
`limit` различных ID. Создать более десяти совпадений и проверить default
`limit=10`, а также разрешённые границы `1` и `20`.

## Invalid, empty и SQL safety

Через executor submission counter с позитивным control доказать:

- каждый `InvalidPlaceQuery` от canonical normalizer возвращается без worker/
  SQL: EMPTY, TOO_LONG, CONTROL_CHARACTERS и NO_SEARCHABLE_CHARACTERS;
- корректный неизвестный query действительно отправляется worker-у и
  возвращает `PlaceSuggestions(items=())`;
- `limit=0`, отрицательный, `21`, `True`, float и string дают `ValueError` до
  worker/SQL;
- non-string query даёт `TypeError` до worker;
- `%`, `_` и `'` внутри валидной строки не получают wildcard или исполняемую
  SQL-семантику и не возвращают prefix-only совпадения.

Пустой успешный результат должен оставаться `PlaceSuggestions`, а не
`InvalidPlaceQuery`.

## Индекс, lifecycle, failures и cancellation

Не копировать production SQL в тест. Установить SQLite trace callback на
owning worker, выполнить настоящий search, взять реально исполненный statement
и прогнать `EXPLAIN QUERY PLAN` для него на том же worker. План обязан содержать
`idx_place_names_search_key`; statement — BINARY lower/upper range и не
`LIKE`.

Дополнительно проверить:

- search реально исполняется на injected worker, не event-loop thread;
- search до open и после close даёт `PlaceCatalogUnavailableError` без SQL;
- реальный read failure после startup становится
  `PlaceCatalogUnavailableError` с причиной;
- детерминированно остановленная worker-operation при отмене task выпускает
  `CancelledError`, после освобождения worker каталог корректно закрывается;
- timeout используется только как защита от зависания; `sleep` запрещён.

Управляемую паузу делать узкой обёрткой вокруг реальной leaf-operation; не
мокать публичный `search()` или результат.
