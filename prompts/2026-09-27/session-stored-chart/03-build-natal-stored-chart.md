# Промт 03. Передача сохранённой карты из BuildNatal в CAS

**Дата:** 2026-09-27.
**Ветка:** `feat/session-stored-chart`.
**План:** [M1-5.2](../../../docs/project_management/implementation_plans/session_stored_chart_implementation_plan.md), карточка 03.
**Статус:** выполнен 2026-09-27.

## Человеческое описание: что и зачем мы делаем

После построения карты приложение уже умеет получить её байты и описать их
контрактом `StoredChart`, но эти части пока не соединены. Поэтому успешный
`BuildNatal` не может передать карту на сохранение, а новая обязательная дельта
сессии делает прежний путь сборки результата невалидным.

Соединяем путь без смены владельца записи: Handler получает готовый артефакт,
готовит безопасный сессионный envelope и возвращает полную дельту. Orchestrator
передаёт именно эту дельту в существующий `ContextService.save`. Если байты
не удалось подготовить или они не проходят проверку размера, сохранения не
происходит и пользователь получает прежний безопасный внутренний отказ.
Журнал должен показывать передачу управления, не раскрывая байты карты.

## Задача

Выполни только карточку 03 плана. Сверь ADR-0040, спецификацию поведения,
действующие требования Handler, sequence 005/010, код и существующие тесты.
Сохрани несвязанные изменения рабочего дерева. Не создавай коммит, ветку,
push или PR.

1. После успешного `ensure_chart` вызови синхронный `artifacts.to_stored` и
   собери `StoredChart` из формата/байт и идентичности артефакта. Включи его
   в полную `StateDelta`. Handler не импортирует кодек и не вызывает session
   storage; Orchestrator по-прежнему один вызывает `ContextService.save`.
2. В `BuildNatalSuccess` проверь, что envelope существует, а его ключ и
   версия равны артефакту; сохрани прежние проверки spec и расчётного входа.
3. Ошибку кодирования и ожидаемые ошибки валидации до CAS переведи во
   внутреннюю `StoredChartPreparationError` с причиной `ENCODE_FAILED`,
   `PAYLOAD_SIZE_INVALID` или `ENVELOPE_INVALID`. У исключения и
   форматированного traceback не должно быть исходного `ValidationError`,
   `input_value` и узнаваемых байтов payload. Не меняй публичный
   `ApplicationInternalFailure`: он остаётся `UNEXPECTED_FAILURE/LOADED`.
4. Добавь INFO send/receive для `to_stored` с фактическим peer,
   `ToStoredRequest`/`StoredChartEncoding` и run_id. При исключении receive
   отсутствует, есть terminal/error. В DEBUG `StoredChart` показывай только
   формат, ключ, версию и размер; успешный расчётный `ChartArtifact` по
   действующему договору логируется полностью.
5. Добавь адресные проверки успеха Handler → Orchestrator → RecordingContext,
   идентичности дельты при save, отказов кодирования/размера/envelope до CAS,
   безопасного traceback, событий и отсутствия вызовов save на отказе.
   Используй существующие fake-порты; не ослабляй module boundaries.

## Приёмка и отчёт

Запусти целевые application unit tests и `tests/test_module_boundaries.py`,
затем связанные application проверки. Отдельно укажи промежуточные падения,
принадлежащие будущим промтам 04–08. Проверь `git diff --check`, запиши в
план точные команды, результаты и предел их свидетельства. Отметь выполненным
только промт 03. SQLite-агрегат и восстановление после рестарта здесь не
реализуются.

## Фактическое выполнение

Handler вызывает `to_stored`, создаёт `StoredChart` и возвращает полную дельту;
`BuildNatalSuccess` сверяет ключ и версию envelope с артефактом. Ошибки
кодирования, размера и валидации до CAS дают безопасный
`StoredChartPreparationError`. DEBUG-сериализация показывает метаданные карты
и размер вместо байтов; INFO фиксирует send/receive `to_stored`. Положительный
тест подтверждает, что Orchestrator передаёт в `RecordingContext.save` тот же
объект дельты, который создал Handler.
Статус реализованного вызова синхронизирован в действующих требованиях
Handler, описании компонентов и README BuildNatal sequence.

Целевой application/boundary-набор: **820 passed**. Расширенный
`tests/application tests/test_module_boundaries.py` вне песочницы:
**949 passed, 14 failed**. Падения относятся к InMemory/SQLite и сквозным
интеграциям: адаптеры ещё возвращают `SessionSnapshot` без обязательного
`chart` (промты 05–07). Полный `pytest`, SQLite-запись пары и восстановление
после рестарта не выполнялись. Точные команды, промежуточный запуск с отказом
pytest temp и пределы свидетельств внесены в журнал плана.
