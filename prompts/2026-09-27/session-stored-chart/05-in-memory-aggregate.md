# Промт 05. Сохранённая карта в InMemory aggregate

**Дата:** 2026-09-27.
**Ветка:** `feat/session-stored-chart`.
**План:** [M1-5.2](../../../docs/project_management/implementation_plans/session_stored_chart_implementation_plan.md), карточка 05.
**Статус:** выполнен 2026-09-27.

## Человеческое описание: что и зачем мы делаем

После успешного построения карты приложение уже передаёт сохранённые байты в
дельте сессии. Сейчас InMemory-хранилище записывает только состояние и
диалог, поэтому при повторном чтении карта теряется. Нужно хранить все три
части как один набор: подтверждённое построение делает текущими состояние и
карту вместе, конфликт не меняет ни одну часть, а сброс удаляет карту вместе
с данными рождения и перепиской.

Это позволит проверить полный жизненный цикл без SQLite и даст общие
контрактные тесты для последующей реализации на диске. Повтор того же
намерения должен вернуть `AlreadyApplied`, оставив карту первого успешного
построения. Возврат к живой сессии должен отдать согласованный снимок без
изменения версии или содержимого карты.

## Задача

Выполни только карточку 05 плана. Сверь ADR-0040, действующие session
requirements, sequence 004/005, `StateDelta`/`SessionSnapshot`, текущий
InMemory adapter и общий conformance. Сохрани несвязанные изменения дерева.
Не создавай коммит, ветку, push или PR.

1. Добавь в общий InMemory backend одну карту `StoredChart` на сессию без
   самостоятельного TTL. Под прежним lock CAS записывает следующую версию
   состояния и карту из полной дельты; при конфликте, отсутствии или
   истечении сессии обе части остаются без изменений.
2. `RESET_DELTA` и равная ему по значению дельта очищают карту и диалог в
   той же секции; aggregate `delete` удаляет все три части. `touch` собирает
   согласованный `SessionSnapshot(state, dialog, chart)` и продлевает TTL
   только после успешной сборки снимка, не меняя `state_version` и карту.
3. Расширь общий conformance наблюдаемыми проверками записи, конфликта,
   гонки двух CAS, точного повтора с `AlreadyApplied` и сохранением
   победившей карты, touch, reset и delete. Используй общие `CHART` и
   `OTHER_CHART` и действующие helpers; не дублируй бинарные фикстуры.
4. Добавь только необходимые структурные проверки InMemory backend. Для
   отрицательных правил проведи положительный контроль, затем временно
   нарушь запись карты при конфликте CAS и перезапись при `AlreadyApplied`;
   покажи ожидаемое падение тестов, убери мутанты и повтори тесты.

## Уточнение границы reaper

Фраза карточки 05 о reaper относится к общему lifecycle агрегата.
Действующие требования закрепляют физическую очистку истёкших строк за
SQLite reaper; InMemory P2 физически не удаляет истёкшую запись. Не добавляй
новый InMemory `reap_expired` и не меняй его семантику истечения. Проверки
SQLite reaper с дочерней картой относятся к карточке 07.

## Приёмка и отчёт

Запусти `tests/session/test_in_memory.py`, затем связанные session/application
проверки. Общие новые conformance-тесты могут пока не пройти на SQLite до
карточек 06–07; зафиксируй это отдельно. Проверь `git diff --check`, внеси
точные команды, результаты и пределы свидетельства в план. Отметь
выполненной только карточку 05; полный `pytest` после всех срезов.

## Фактическое выполнение

Общий InMemory backend хранит `StoredChart` по `session_id`. CAS под прежним
lock записывает state и chart, reset очищает chart и dialog, delete удаляет
все три части. `touch` до продления TTL проверяет согласованность
`SessionSnapshot(state, dialog, chart)`; содержимое карты и версия состояния
не меняются. Истёкшая InMemory-запись остаётся физически на месте до delete,
как требует действующий P2-контракт; новый reaper не добавлялся.

Общий conformance расширен проверками первой записи, перестроения, конфликта,
гонки CAS, точного повтора с `AlreadyApplied`, пустого и заполненного touch,
reset и delete. Положительный commit возвращает `CHART`; временная запись
карты проигравшей дельты при конфликте обрушила оба conflict-варианта и
проверку `AlreadyApplied` (**3 failed**). Мутант удалён; повтор этих тестов
дал **3 passed**.

Исходный InMemory-набор останавливался после **88 passed, 5 failed**: `touch`
не передавал обязательное поле `chart`. После изменений финальный целевой
набор: **124 passed**; связанный session/application/boundary-набор:
**312 passed**. Один адресный SQLite conformance-тест ожидаемо падает:
SQLite `touch` пока создаёт `SessionSnapshot` без `chart` (карточки 06–07).
`git diff --check` прошёл; полный `pytest`, SQLite aggregate и restart в
этой карточке не проверялись. Точные команды и пределы свидетельства
записаны в журнал плана.
