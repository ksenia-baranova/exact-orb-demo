# Промт 04a. Поправки RED-тестов после независимого ревью

**Статус:** выполнено 2026-10-01; app-зависимый RED сохранён до промтов 05–13. **Зависимость:** тесты 01–04.
**Источник замечаний:** ревью исполняемых тестов другой моделью, переданное пользователем 2026-10-01; решение о составе поправок принято после сверки с текущими requirements, G0 и кодом. Формальный Tester review пользователь ранее исключил из порядка работ.
**План:** [M1-6 implementation plan](../../../docs/project_management/implementation_plans/http_api_and_session_middleware_implementation_plan.md), карточка 04a.

## Задача

Исправь ложные RED: обеспечь разные `ResolvedBirthData` для разных намерений в конкурентном SQLite-тесте; сравнивай build chart с полной проекцией `ChartDTO`, а не сокращённым примером; передавай повторяющиеся Cookie как пары заголовков; в disconnect/capacity тесте удерживай permit только пока действительно живёт неотменяемая работа. Сохрани отдельный сценарий обычной отмены до commit. Не требуй ответа после disconnect, если это не следует из публичного контракта.

Уточни общий тестовый шов: один построитель настроек для `app_client` и lifecycle с явно указанными умолчаниями в G0. Фабрики G0 остаются без аргументов; каталог может замыкаться фабрикой runtime. Убери неподтверждённые assertions об ответах GET после disconnect, сохрани доказательство ожидания executor future при shutdown.

Усиль проверки квот сценарием, в котором отказ происходит позже допущенного события и следующий допуск проверяется на границе первоначального окна. Для renew проверяй тот же session ID и атрибуты cookie; для clear проверяй `Secure` и `Path=/`. Отдельно проверь invalid/duplicate cookie у build до admission и Orchestrator, а также одновременное резервирование последнего слота. Раздели проверки событий `http_cookie_replaced` и `chart_unavailable` от основных маршрутных сценариев, сохранив их отдельное покрытие. Добавь отдельный валидный cosmogram sample с непустыми `excluded_aspects`, которые projector не публикует; компактный golden sample и существующий golden не меняй.

Замени слишком широкие ожидания `Exception` в projector/startup проверках на типизированные причины отказа. Общие тестовые helpers вынеси из test-модулей; устрани косметическое сравнение spy-кэшей, повторный HEAD и неточное имя теста про resolver. Не фиксируй приватные имена логгера, формат строки события и `active_bucket_count` как публичный G0 API; где возможен публичный oracle, предпочти его.
Объяви `httpx` прямой dev-зависимостью уже в этом test-only срезе.

Пометь пример build response в §6.4 как сокращённый. Уточни начальный момент reaper и code для повторного `query` без нового ADR, если это лишь разъяснение действующего поведения. Вопросы, требующие изменения публичного контракта, зафиксируй отдельно и не решай молча. Сохрани журнал команд и результатов RED в плане; прежние промты 01–04 не редактируй.

## Приёмка

Запусти независимые pure/SQLite тесты, затем весь `tests/http_api` для ожидаемого RED, `compileall`, `git diff --check` и проверь имена изменённых файлов. Укажи точные команды и результаты; отсутствие HTTP transport не называй успешной проверкой app-зависимого поведения. Production code, golden существующего контракта, commit, push и PR не меняй.
